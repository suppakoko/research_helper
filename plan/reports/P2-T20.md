### Design decisions recorded in code (summary)
- **`languages`** → in-term clause `eng[la]`, several values as `(eng[la] OR fre[la])`, joined to the Boolean term with `AND`, before the date clause in the preview. Values pass through verbatim after the same Entrez-syntax cleaning as any term; a non-empty list that cleans to nothing throws `RangeError` (emitting no clause would silently widen to all languages). Empty list == absent (byte-identical URL).
- **`openAccessOnly: true`** → `RangeError` naming the member and `PUBMED_QUERY_FILTER_SUPPORT.openAccessOnly`; `false` == absent. The pipeline's `fetchOne` (`stages.ts`) already converts an `explainQuery` throw into that source's `report.error`, so the user sees a per-source error rather than a quietly smaller count.
- **`raw`** → a bag of extra `esearch` parameters, appended after `maxdate` and before `api_key`/`tool`/`email`, sorted by key (byte-stable for fixture hashing), key and value both `encodeURIComponent`-ed, value `String(value)`. It **never touches `term`**: `term` and every other name the module emits (`PARAM_ORDER`) plus `reldate` (conflict C10) are reserved and refused with `RangeError`, so `raw` can neither replace nor extend the parsed query nor displace the D10 identification or the credential. `raw` is not shown in `explainPubmedQuery` (it is not a term); it is visible in `PubmedEsearchRequest.transmittedQuery`, and `redactUrl`'s backstop still strips a credential-shaped raw name (`token`) from the stored URL.
