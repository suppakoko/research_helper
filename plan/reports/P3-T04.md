  "> **Corrected 2026-10-23 (`P3-T04`; measured in the `omni.ja` files of Zotero 10.0.3).** Two controls in the markup above cannot be built as drawn, and the pane ships them differently:
  1. **The base-URL input carries no `preference=` attribute.** Zotero's `_syncToPrefOnModify` (`chrome/content/zotero/preferences/preferences.js`) writes the element's value on every `input`, `change` and `command` event, and its `beforesynctopreference` event is a plain, non-cancelable `Event` dispatched after the value has been read, so a bound field stores every keystroke and cannot refuse a value. `03-llm-provider-integration.md` §14.4 requires the value to be validated at write time, so `preferences.js` sends it on `change` through `PreferencesHostApi.setBaseUrl`, which writes `<provider>.baseUrl` only for an absolute `https://` URL with no trailing slash, no user name or password, no `?` and no `#`, or for an empty value. Anything else is refused with a message and the stored value is kept. The placeholder is still the documented base URL. This is a fourth control in the table above.

The input accepts any model ID, as `07-architecture-and-data-model.md` §8.5 allows; offering the catalogue's models as suggestions is `P3-T14`'s."

CONTRADICTIONS/FINDINGS
1. **Two markup items in the card cannot be built as written** (Do step 1 and docs/08 §7.3); both were measured in Zotero 10.0.3's `omni.ja`.
   - "The base-URL input bound to `<provider>.baseUrl`": Zotero's binding writes every keystroke and has no cancelable hook, so it contradicts Do step 3 and docs/03 §14.4's "validated at write time".
   - "The model menulist": editable XUL menulists no longer accept typing.
   - What was built instead: the base-URL field is written only through the host's `setBaseUrl`, after validation; the model control is a text input bound to `<provider>.model`. The Done-when line "every `preference=` names a key in src/prefs/keys.ts" still holds and is tested. The docs/08 note records why; the owner may want to confirm.
2. **Base-URL rules, as built:**
   - Surrounding whitespace is trimmed before checking, which is the same trim the resolver applies.
   - Refused without rewriting: anything not starting with `https://`; a trailing slash; a user name or password; `?` or `#`; a value that does not parse.
   - The call-time resolver (`src/llm/shared/baseUrl.ts`) still strips a trailing slash from a value written some other way, for example through about:config. The pane is stricter than the resolver, never looser.
3. **The restore notice tests "no key stored at all"** with `listStoredIds()`, not the six `present` flags. A lone `tts.gemini` key sets `gemini.keyPresent` but has no block in the pane, and the card's condition is "every `*.keyPresent` false".
   - "Plugin database non-empty" means any row in any table except `schema_version`, cache rows included.
   - So someone who has used the plugin but never stored a key also sees the notice. The wording is conditional ("If you restored or copied…").
4. **The restore sentence now appears up to seven times.** P1-T44's per-field `research-helper-prefs-key-absent-os` still repeats it on every empty field under an operating-system store, so with six blocks the sentence shows six times plus the new notice. The per-field behaviour was left unchanged.
5. **The LLM status line for a stored key reads "A key is stored. Not tested yet this session."**, and the Test button is disabled until P3-T14 adds the Test call and the stored result.
6. **For G-19:** while tier 2 is active, risk paragraph 1 ("encrypted using your operating system's credential store") is not true. The badge says "Not saved between sessions", but docs/09 §1.8 has no tier-2 sentence. This is an owner decision on docs/09 §1.8's text.
7. **The `useTranslators` checkbox is not built.** The en-US bundle comment and plan/03 (P2-T18) say this pane's checkbox is P3-T04's, but the card's Do steps and the coordinator's brief do not include it. Reported, not built.
8. **P3-T15's finding 1** (show the paid declaration in the model picker) was not done. The model suggestions are P3-T14's.
9. **Wiring change for other callers:** `PreferencesHostDeps.providerPrefs` is now required. Any other caller of `createPreferencesHost` must pass it; only `registerUI.ts` and the two test files call it today, and all three were updated.
