## What was built

`fanOut(options)` takes the resolved sources, the query/limit/recency input, the run token, the clock, the `Fetching` stage reporter, a logger and an injected `Semaphore` (the `network-metadata` pool). For each source it: builds the `SourceQuery` with `parseUserQuery` and `resolveDateFilterMode` (same logic as the pipeline's private `queryFor`); creates a per-source cancellation token linked to the run token; takes a pool permit; arms a 20 s deadline on the injected clock; drives `searchAll`; on the deadline cancels only that source's token with `{ kind: "timeout" }` (which aborts its in-flight request through `cancellerReceiver`) and records a `TimeoutError`; on any other throw records that source's `SerializedError` and raises the FR-9 banner "`<source>: <CODE> — the other databases were still searched.`"; keeps the records a source yielded before failing; applies the client recency filter; and returns records and reports in source order. Results are gathered with `Promise.allSettled`, so the run's `OperationCancelledError` is thrown only after every in-flight adapter promise has settled and every deadline timer is disarmed. Page warnings an adapter raises through `SourceCallContext.progress.warn` (the only route out of `searchAll`, which the PubMed adapter already uses) are captured onto that source's report and still forwarded once to the reporter tree. No retry or backoff is added here.

The 2 s figure is asserted on wall-clock, but with cooperative fakes it is a formality; the real 2 s budget is the HTTP layer's `cancellerReceiver`, which this layer-1 test cannot exercise.
