CONTRADICTIONS/FINDINGS
1. Key with the full version string or with cacheEpoch (item 239(a)): I chose the full version string, which matches docs/06 §11.2, docs/12 §17.4 and card steps 1 and 5. docs/12 §17.2's PATCH-retention promise therefore does not hold; owner to confirm or to amend §17.2.
2. docs/07 §9.3's tag form `promptVersion:<v>` would invalidate every prompt's entries at once, because every prompt is at 1.0.0. The tags are now qualified by the prompt, and docs/06 records this. docs/07 §9.3 itself is not edited.
3. Prompt metadata in the key is my own addition, not in §11.2, made under the "never a different input" rule. Editing a title or tag in Zotero will re-pay for that item's summary. The owner should confirm; dropping it is one line in summaryKey.
4. ignoreModel uses a pointer entry so that summaries written before the option was switched on are found. The provider stays in the key. docs/07 §9.3 trigger 2 (invalidate by model:<old> when the model changes) is not built and would work against ignoreModel; whoever builds it must take that into account.
5. Commas in work keys: P3-T17's RunningWork.pinnedTags writes the raw `work:<key>`, while I escape commas and percent signs (a raw comma makes the cache refuse the tag). A work key containing "," or "%" (possible in a DOI) is therefore stored, but its pinned tag does not match, so a running job does not protect that entry from eviction. The fix is for pinnedTags to apply encodeTagValue as well (queue.ts; not mine).
6. skipCached cannot decide anything without the text's hash, because the key needs the acquired text and that means reading the item again. It is built with an optional probe. Without a probe it returns the checkpoint unchanged:
   - the spend guards may over-count and never under-count;
   - at run time a cached item still makes no model call.
   - P3-T29 must pass a probe (which needs a container edit), and its probe must answer "true" only when the item also needs no further write, because the guard moves those keys to `completed`.
   - Resumption still waits, because the egress, confirm and ceilings guards and the notifier are missing.
7. Concurrent requests for the same key share one model call only inside one SummaryCache instance (one per job). Two jobs summarizing the same item at the same moment could each pay once; exclusivity keys normally prevent that.
8. docs/07 §8.3's authoritative `summary` table, which holds the StoredSummary rows, still does not exist; this cache is not that store (P3-T25).
9. The Done-when line "`npm run typecheck` exits 0" currently fails only because of P3-T04's files that are still being edited.
