### How `normalizeForSource` works

Signature: `normalizeForSource(node: QueryNode, capabilities: Pick<SourceCapabilities, "keywordSearch"> & { or; not; phrase; fields: readonly QueryField[] }): readonly QueryNode[]`.

- The second argument is the source's `keywordSearch` flag from `docs/07` §4.2's `SourceCapabilities` (taken by `Pick`, the same shape `resolveDateFilterMode` in `recency.ts` uses) plus that source's `docs/02` §12.3 column: whether OR, NOT and phrase are real operators, and which `QueryField` members it renders.
- Returns the nodes the source cannot express, in document order, **by reference** (the actual objects in the tree, so a renderer can skip them by identity). Empty when everything is expressible.
- `keywordSearch: false` returns exactly one entry, the root — the signal to emit no query (bioRxiv, `docs/02` §8.4, the card's Do NOT).
- `and` nodes, unfielded terms and `field: "any"` are always expressible (§12.3's AND row has no n/a cell; `"any"` is the absence of a field and is what the fallback node carries).
- The walk continues below a reported node (an OR that cannot be rendered and a phrase inside it are two different losses). The input is never modified.
