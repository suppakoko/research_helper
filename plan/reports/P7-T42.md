## What changed

- `src/ui/dialogs/summarizeDialog.ts`: each row of the window's model carries the key of its item
  (`SummarizeWindowRow`, a `FluentLine` with `key`; `buildSummarizeWindowModel` sets it from the run view's
  `itemKey`). The Fluent id and its arguments are unchanged. `docs/07` declares no type of this model (grep,
  2026-11-25), so the type lives beside the builder. Its caller, `createSummarizeSession` in
  `src/bootstrap/registerUI.ts`, passes the model on unchanged and is not modified.
- `addon/content/summarize.js`, `renderRows` (called by `render`): one `<p>` per row key, kept between updates in
  `state.rowElements`. A row's Fluent attributes are set again only when its id or arguments change (compared as one
  JSON signature). A row is created only when its key is new, removed only when its key goes, and moved only when
  the order changes. A row with no key, as an older model drew it, is keyed by its place. The elements are the same
  XHTML `<p>`s in the same container, with the same Fluent id (`research-helper-summarize-row`) and arguments, so the
  window's text, accessible names, Fluent ids and keyboard behaviour are unchanged. No Korean or English text was
  added or changed.
- Not changed: `place`, which sets the window's eight single lines (header, stage, progress and the rest) on every
  update, as before. Those are eight elements, not a list, and are outside this card's Files and Do (coordinator,
  `plan/00` §6 item 414).

## Tests (Do step 2)

**Unit** (`test/unit/ui/summarizeDialog.test.ts`, describe "P7-T42"; 11 tests): the shipped `summarize.js` is
evaluated with `new Function` against a fake document (as `searchDialog.test.ts` does), so the tests run the code
that ships. They check that:

- each model row carries its item's key beside the unchanged Fluent line;
- the first draw makes one XHTML `<p>` per row, in order, each set once;
- **an update that changes one row sets that row's element only, and every other row keeps its element** (identity,
  by `toBe`);
- an update that changes nothing sets no row and creates nothing;
- a title change is a change;
- a row that goes is removed, and only it; a row that appears is added in its place; a new order moves the same
  elements;
- 500 rows that settle one at a time make 500 elements in all, each set once per change;
- rows without a key are kept by place;
- `render()` sends the rows down the same path.

Against the code before this card (K0: the old `summarize.js` put back for one run), 9 of the 11 fail; the two that
pass are the model's keys and the first draw, which the old code also met.

**Integration** (`test/integration/workloadMemory.spec.ts`): `watchRows` counts, with a `MutationObserver` of the
window's own on the rows' container (children only), the elements each summarize job adds and removes;
`assertRowsKept` asserts one added per paper, none removed and one row per paper at the end, in each of the five
reference jobs and in the 500-item job. The observer is disconnected before the window closes, and the 500-item job's
closed window is still freed (asserted where a closed window can be freed). A new log line gives the 500-item job's
row counts and its longest gap beside the accessibility service's state, which `P7-T42`'s first `Done when` line
(service on) and `P7-T41`'s (service off, item 413(b)) are read by.
