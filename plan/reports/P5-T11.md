Nothing else about the item leaves the machine (`docs/09` §3 row 2). So the diagram's "0–1 requests" holds for a seed with an identifier; a title-only seed costs 1 request without a key and 3 with one (two title asks and the `lookup`), plus one converter request in the corners above.
>
> **The threshold. DECIDED 2026-11-01 (coordinator, under `plan/00` §6 item 313; `plan/08` §0.4 line 9).** A candidate passes when, on `normalizeTitle`'s form of both titles:
>
> - `levSim` ≥ `LEVSIM_DUPLICATE_THRESHOLD` (0.95), or
> - `levSim` ≥ `LEVSIM_CORROBORATED_THRESHOLD` (0.88) with |year delta| ≤ `MAX_YEAR_DELTA` (1) and the first author's family name matching.
>
> No constant is respelled: `src/sources/shared/dedupe.ts` declares them, so tuning them for deduplication moves this threshold too. This is not the cascade's table of `docs/02` §11.3.3: the 0.95 row asks for no year, because a title-only item often has none, and the 0.88 row asks for no Jaccard score. Exactly one passing work resolves, flagged "matched by title". Two or more means the user picks (FR-14 scenario 2). None is an error naming DOI, PMID, arXiv ID and title.
>
> **DECIDED 2026-11-02 (coordinator, under `plan/00` §6 item 313), additions to the threshold:**

> 1. `docs/02` §11.3.3's false-positive guards apply, because they name a wrong paper here as they name a wrong merge there. Titles whose series marker or any number differs never pass. Text cannot do this: the recorded `10.1021/jacs.5c03749.s001`, a Crossref `component` with `[[null]]` dates, has what reads as a whole article's title, so a seed with that title compares at 1.000. ## Findings

1. **The threshold is unmeasured.** The evidence is one real Crossref query with no candidate in the 0.88–0.95 band, so the corroborated row has met no real title. The Semantic Scholar stand-ins are no evidence at all. I added the `P5-T30` note as what measures it: known-DOI items resolved with the DOI withheld, where a wrong DOI reopens the threshold. This is a coordinator-level choice you may overturn.

2. **The key gate has a real gap, confirmed by running it on the scratch copy only.** `hasApiKey` asks `secrets.has`, while `lookup` goes through `issue`, which reads the key with `resolveApiKey()` and carries on unkeyed if the value is unreadable or blank. I ran `expandSeedIds` on a DOI seed with two stores: `has` true with `get` throwing, and `has` true with a blank value. In both, `hasApiKey` returned true and one POST to `/graph/v1/paper/batch` went out with no `x-api-key` header (headers `Accept`, `Content-Type`, `User-Agent`). That breaks `plan/08` §0.2 item 19 in this corner only. The request carries the seed's identifier, not the abstract, notes or tags. `seed.ts` cannot close it, because `hasApiKey` is the only gate it has, and the code sits in `semanticscholarSource.ts`, outside my Files. I recommend a keyed-only lookup that returns `[]` when `resolveApiKey` gives nothing, as `matchTitle` does. Plain `lookup` must stay as it is for its keyless backfill use. I have not checked whether other Phase 5 callers pair `hasApiKey` with `lookup` the same way. The case is narrow and does not make a card on its own under rule 9, unless you read the finishing condition "no Semantic Scholar request without a key" as covering a broken keychain.

3. **Seed requests are outside the budget.** Seed resolution's 0–3 requests do not pass through `RequestBudget`. `docs/05` §6.1's "0–1" holds only for identified seeds, and the note says so. `P5-T14` decides whether to count them.

4. **`P5-T12` has overlapping seed logic.** `src/pipeline/related/generators.ts` holds a private `expandSeed` (a Europe PMC lookup for a DOI-only seed), a private `ExpandedSeed` interface and its own arXiv DOI logic. It complements `expandSeedIds`, and the names do not collide because its type is private, but the arXiv rule now exists in two places. `RelatedGeneratorSeed` is `{ids: Partial<ExternalIds>}`, and `expandSeedIds(...).work.ids` fits it.

5. **`merge` and `type` `"other"`.** The `merge` issue from `P5-T09`'s finding can affect a merged candidate's `type`. `P5-T12` owns `merge.ts`, and my tests do not depend on the outcome.

6. **Non-Latin first authors cannot corroborate.** `normalizeFamilyName` keeps only a–z, so Korean or other non-Latin first authors never pass the 0.88 row. They can still pass the 0.95 row. This is a known deduplication limit that now also applies to title matching.

7. **A dated `component` is not rejected.** A dated component, if one exists, reaches the `"choose"` list visibly. Two recorded components are all the non-paper rule rests on.
