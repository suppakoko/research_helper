## Findings

None blocks a phase's finishing conditions, so none needs a card.

1. **A key that disappears mid-run can poison the cache for a week.** The probe is read once at the start. If the user clears the key after that, `lookupKeyed` answers `[]`, and `lookupThroughCache` stores "missing" rows for up to one batch of Semantic Scholar metadata for 7 days. The window is narrow and the cost is limited to missing metadata, so it is recorded and not coded.

2. **`hasApiKey` now has no caller in `src`.** Only tests call it. It stays because `docs/07` §4.2 names it and because it does not decrypt, so a window can use it for display. `P5-T16` can decide.

3. **A seed with no vector gives no notice.** On a keyed run, every candidate's similarity is then 0 and the report still reads `specter_v2` with no notice. This follows the card's rule. `P5-T30` could show how often it happens.

4. **Every run reads the whole library twice.** `findExisting` needs one index and `matchAgainstLibrary` needs the other, and `readLibraryWorks` maps every regular item. The cost on a large library is unmeasured. Item 106 and `P5-T30` are where it belongs.

5. **The card's note says seed resolution sends 0–3 requests; the code allows 4.** The most is two title matches, a lookup that finds nothing, then the PMC converter. `docs/05` and `estimate` use 4.
