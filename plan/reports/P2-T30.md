## Contradictions with the card or corpus

1. **Step 2 says "make `dedupeAndMerge` asynchronous"; doing so literally breaks a file outside `Files`.** `test/unit/model/merge.test.ts` (not in the list) calls `dedupeAndMerge` synchronously at six sites and reads `result.works` etc. Per `plan/README.md` §4's importer rule ("if an importer is outside your Files list, extend the file and report it") I kept `dedupeAndMerge` synchronous and added `dedupeAndMergeAsync`; `run` awaits the async one. Same for step 1: `dedupeRecords` is kept because `dedupe.test.ts` (many sites), `merge.test.ts` (via `dedupeAndMerge`) and the sync `dedupeAndMerge` need it; `matchAgainstLibrary` does **not** call `dedupeRecords` (it runs its own loop over `compareCandidates`) and was not changed.
2. **"Yields between blocks" taken literally would cost a timer tick per bucket.** The 500-record synthetic set has 50 blocks; real result sets have many singleton buckets. `dedupeCascade` yields at a block boundary only if at least one comparison happened since the last yield — a singleton bucket is not a yield. The 50-block set still yields 50 times (asserted). Stated in the generator's doc.
3. **The card names `src/core/`'s yield/clock primitive; `Clock.sleep` cannot be the one `run` passes.** Every pipeline unit test builds its `PipelineContext` with `createManualClock`, whose `sleep` resolves only on `advance()`, so `ctx.clock.sleep(0, ctx.token)` as the yield would deadlock every merging unit test. The default yield therefore is `createSystemClock().sleep(0)` inside `dedupe.ts` (reusing the core primitive, not inventing one), and the yield is injectable (`DedupeAsyncOptions.yieldToEventLoop`, `SearchImportDeps.yieldToEventLoop`) exactly as `ImportRequest.yieldToUi` is in `importer.ts`.
4. **`plan/00` §6 item 119 is already struck through** in the index (`~~…~~`), although the card lists it under `Retires` as open. Not my file; noting it.
5. **The 4 851 figure is C(99, 2), not C(100, 2).** With the `stubRecord` titles, `blockingSignature` puts 99 records in one block and one (record 100, whose "100" token ties with the three-letter tokens) elsewhere — a fixture artefact that changes nothing here.
