## What was done

1. **The mark (step 1).** `recordFromSemanticScholar(extra)` in `src/zotero/bibliography.ts` reads `extra` only when
   it is a string. It is true when `extra` has an `rh-s2-corpus-id` line, or an `rh-sources` line whose
   comma-separated entries include `semanticscholar` after trimming. `formatBibliography` sets
   `BibliographyEntry.semanticScholar: true` on such an entry (a new optional member in `src/model/trend.ts`, recorded
   in `docs/07`).
2. **The line (step 2).** "Some records: Semantic Scholar, Allen Institute for AI."
   (`DEFAULT_SEMANTIC_SCHOLAR_ATTRIBUTION` in `exportMarkdown.ts`). `needsSemanticScholarAttribution` decides whether
   to print it. It is printed under the numbered entries and before the retracted list in:
   - the Markdown export (`bibliographyBlock`, escaped as Markdown text);
   - the report note (`bibliographyHtml`, escaped as HTML);
   - the scaffold (`bibliographyBody`).

   A retracted entry is not cited, so it does not count. The label reaches the renderers from
   `trendReportPipeline.ts` (the note) and `registerUI.ts` (`labelsOf`, the export).
3. **The Korean (step 3).** The line is report text, so it follows `reportLabels.ts`'s rule, not Fluent:
   - the English entry is in `EN_REPORT_LABELS`;
   - the key is on `KO_REPORT_LABELS_PENDING_REVIEW`, with the draft "일부 기록 출처: Semantic Scholar, Allen Institute
     for AI." as a comment above it;
   - a Korean report prints the English line until `G-41`;
   - `l10n.spec.ts` and the unit test of the pending list now expect `["semanticScholarAttribution"]`.

   The draft is in `plan/reports/ko-review-p7d-draft.md`.
4. **Docs.** `docs/07` gives the `BibliographyEntry.semanticScholar` member with its doc comment. `docs/09` §7 has a
   note under the Semantic Scholar line.

## Mutation sweep

16 mutants over `bibliography.ts`, `exportMarkdown.ts`, `noteHtml.ts` and `scaffold.ts`. **16 of 16 killed.** One
mutant at first survived: "non-string extra read" (reading `extra` through `String()`). A test was added in
`bibliographySource.test.ts` with an object whose `toString` returns a marking line, and the mutant was then killed.

## Findings (not cards, rule 9)

- A record is marked by its `rh-sources` line or its `rh-s2-corpus-id` line. With the sources line turned off, a
  Semantic Scholar record that has no corpus id would not be marked.
- A report stored before 2026-11-17 has no mark and prints no line until it is made again.
