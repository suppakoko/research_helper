**COORDINATOR-LEVEL DECISIONS YOU TOOK**

Decisions 1 to 6 are written into `docs/07` §9.2. Decision 7 is recorded here and shows in the declarations printed there; it did not get its own DECIDED line. These still need recording in `plan/00` §6.

1. **"Permanent" is 100 years (`RELATED_PERMANENT_TTL_MS`) in `source-response`.** `Cache` cannot say "never" there: an omitted `ttlMs` silently takes the namespace's 24 h, so the ID cross-walk would have expired daily. Size eviction still applies.
2. **Nine of `docs/05`'s ten rows pass through the wrapper.** The SPECTER2 row does not, because §9.2 puts vectors in the `embedding` table (`P5-T03`, `P5-T20`). A parity test reads the `docs/05` table and holds the other nine equal.
3. **A negative entry belongs to one signal of one key, not to a paper.** A seed no source knows therefore costs one request per signal, once per 7 days. Only `BadRequestError` with `httpStatus` 404 writes one from `cachedRelated`. `writeRelatedMissing` covers an unresolvable id inside a good answer, such as `/paper/batch`'s `null`.
4. **Values pass `redactRecord` with `RELATED_VERBATIM_KEYS`, and the mark is stored.** A fresh answer is returned as gated, so a call answers the same whether or not it came from the cache.
5. **Key gating.** `params` are gated, and a credential-named field throws `RangeError` before anything is sent. `ids` and `negativeIds` are not gated, or two 40-hexadecimal papers would collapse into one key.
6. **`cache.enabled` off gives `NO_CACHE`.** A failing cache only warns (error name and signal kind, never the value), and the request goes ahead.
7. **Signature change from the card.** `cachedRelated(deps, kind, key, fetch)` takes `{cache, logger}` rather than `cache`, because a swallowed cache failure must still warn. The key is `cacheKey("source", sourceId, kind, ids, negativeIds, params)`, which is `docs/07` §9.1's `sourceResponseKey` shape.

No preference was read beyond the existing `cache.enabled`, and nothing was taken from `P5-T02`. The run's budget size is not in this card: `RequestBudget` takes it as a constructor argument, and 40 stays `P5-T23`'s default.

**CONTRADICTIONS/FINDINGS**

1. **The instruction "use `redactRecord` for persisted records" would have destroyed every Semantic Scholar record if followed plainly.** Measured over recorded fixtures through the shipped mappers: with no verbatim names, the gate rewrote `id`, `nativeId` and `work.url` on 202 of 202 Semantic Scholar records. With `RELATED_VERBATIM_KEYS` it changed nothing on those 202, on 317 Europe PMC records or on 80 Crossref records. PubMed and arXiv records were not measured. `P5-T03` faces the same trap (`P5-T01` finding 7).
2. **`url` is copied unchanged, which is a small hole in the gate.** It comes from the source's answer. I grepped the Semantic Scholar, Crossref and arXiv mappers, the ones that set `url`, and it is not built from a request URL, so no key of ours can be in it. `pdfUrl`, `landingPageUrl` and all text stay gated, and a test holds that.
3. **`plan/08` `P5-T10` "`docs/05`'s ten ship, each through `ttlMs`" is true of nine** (decision 2). The card needs a dated note.
4. **`RequestBudget` now names two things:** the new class, and the time-budget interface in `src/core/http/retry.ts`. I kept the name because `docs/05` and `plan/08` use it. Both file headers and `docs/07` §9.2 say so. Nothing imports both today.
5. **`getOrCompute` was not used,** because one call cannot store two lifetimes (value and negative). So two concurrent identical calls send two requests. No card's flow issues the same key twice at once.
6. **A taken share is not given back.** A generator that fails part way keeps its budget spent. This is deliberate and simple.
7. **Findings for later cards:**
   - With `logRequestBodies` on, a record's `raw` would be stored in the cache for up to 90 days, gated. `P5-T12` and `P5-T23` should drop `raw` before caching.
   - `fanOut` has no cache hook, so `P5-T23` step 1(d) must wrap one source and one query at a time, as `plan/08` §3's "one-query call" says, because `RelatedCacheKey.sourceId` is singular.
   - `P5-T11`'s `matchTitle` has no signal kind and no row in `docs/05` §9.2, though `plan/08` §0.2 item 21 says "every relatedness response". Recommended: leave title matches uncached, and say so on `P5-T11`.
