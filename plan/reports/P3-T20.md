FOR THE COORDINATOR'S LABELLING PAGE (the contract ingestion expects)
- **Collection:** one document per paper, doc id = paper id.
- **Document shape:** `{ headings: [{offset, line, label}], added: [{line, label, occurrence?}], hasImradStructure: true|false, updatedAt? }`.
  - `offset` and `line` must be copied exactly from `candidate-headings.json`.
  - `label` is one of "introduction", "methods", "results", "discussion", "results+discussion", "other", "not-heading".
- **Defaults the page should show:**
  - A candidate the owner leaves unmarked counts as not-heading.
  - A paper stays pending (no labels file, manifest value null) until `hasImradStructure` is true or false.
- **Owner-added headings:** matched to a line whose trimmed text equals the given text. Failing that, a line that starts with the text followed by a space or punctuation (a run-in heading). `occurrence` (1-based) is required when several lines match.
- **Export file:** may be an object keyed by doc id, or an array of documents carrying `id`, `doc_id`, `docId` or `_id`, with the fields inline or under `data`. Either may sit under a top-level `docs`, `documents`, `items` or `rows`.
- **Running it:** `npx tsx scripts/build-imrad-fixtures.ts ingest <file>`, then `validate`. Ingestion writes nothing at all if any document has a problem, and lists every problem.
- **Mapping:** results+discussion becomes `["results","discussion"]`, other becomes `["other"]`, not-heading is dropped.

CONTRADICTIONS/FINDINGS
1. **Files list.** The card does not name `scripts/imrad-fixtures/extract.spec.ts` (needed, see FILES), `labels/.gitkeep`, or `candidate-headings.json` (named in my brief, not on the card).
2. **Columns cannot be seen in the extracted text.**
   - Zotero 10.0.3's extractor writes one line per text block, so a paragraph is one line. That includes S1, a BMC article.
   - docs/06 D-06-4 (2026-09-16, Zotero 10.0.2) says a BMC article emitted one `\n` per printed line. That no longer holds for S1 on 10.0.3. I did not edit D-06-4.
   - `columnCount` is therefore observed on block geometry from the plugin's own `getStructuredDocumentText`. The rule and per-paper evidence are in the README and the sidecars.
   - Result: 27 two-column and 13 single-column. This agrees with the candidate list's expectation on 38 papers.
   - N6 was not checked in advance and measures single-column.
   - E2 (iScience, Europe PMC's PDF render) was expected two-column but measures single-column (3 of 16 pages).
3. **XR2's date was wrong in the candidate list.** It said 1972; the report page reads "DECEMBER 1974". I corrected the manifest venue, XR2's sidecar and the README.
4. **For P3-T22 and plan/00 item 258: the OCR probe does not separate the scans.** No paper got `ocr_suspected`, including the OCR'd X1 and X2, whose text is visibly garbled ("bas ic mechani sm").
   - Lowest alphanumeric-plus-punctuation shares: X1 0.823, A4 0.824 (born-digital), E4 0.826, X2 0.830. The 0.80 threshold flags none of them.
   - All figures are in each sidecar's `extraction.diagnostics`.
5. **For P3-T19 / P3-T22: the cleaning pass leaves some running heads and some reference lists.**
   - W2 still holds 7 copies of the Wiley footer "Adv. Sci. 2023, 10, 2301332 © 2023 The Authors…". It is followed by blank lines before each page separator.
   - The reference cut was not applied on X1, A4, X2, W1, W2, E2 and W3.
   - Reported only. The committed text is what the plugin produces today, so labels must index into exactly this text.
6. **The candidate list is long for some papers:** A5 760, A4 726, W5 489, S4 435, W4 393, A1 392, O3 320. These texts come out one printed line per line, or have many short table, equation or figure lines. Per my brief the rule errs towards too many lines; the coordinator may want paging or filtering on the page.
   - A heading run into its paragraph is not a candidate, because the whole line is longer than 120 characters. The owner adds such a heading by its line text.
7. **A rebuilt text that changes will invalidate the labels on purpose.** Labels are bound to the text's SHA-256, so a later change to the cleaning pass or a Zotero upgrade makes every labels file fail validation rather than silently shifting offsets. Re-labelling, or re-mapping offsets, would then be a deliberate step.
8. **The build adds one structured-document read per PDF** (for the column count) on top of the one acquisition already makes. Each paper took 0.4–2.6 s in all.
