**The `LLMRouter` shape as declared** (`docs/07` §4.3, `src/llm/types.ts`)
```ts
export type ModelTier = "cheap" | "standard" | "strong";
export type ModelPurpose = ModelTier | "screening";
export interface ResolvedModel {
  readonly providerId: ProviderId;
  readonly modelId: string;
  readonly fromPref: string; // e.g. "summaryModel", "openrouter.model"
}
export interface LLMRouter {
  activeProvider(): ProviderId;
  resolveModel(purpose: ModelPurpose): ResolvedModel;
  chat(request: ChatRequest, ctx: LLMCallContext): Promise<ChatResponse>;
  chatStream(request: ChatRequest, ctx: LLMCallContext): AsyncIterable<ChatStreamChunk>;
}
```
- **Model chains.** The first non-empty value wins:
  - `cheap` and `standard`: `summaryModel`, then `<provider>.model`.
  - `strong`: `reportModel`, then `<provider>.model`.
  - `screening`: `screening.model`, then `summaryModel`, then `<provider>.model`.
  - If every value in the chain is empty, `resolveModel` throws `ConfigurationError` and never makes up a model id.
- **Before dispatch**, in this order:
  1. A cancelled token throws `OperationCancelledError`.
  2. No `<provider>.keyPresent` throws `MissingCredentialError`.
  3. A key flag with no registered adapter throws `ConfigurationError`.
  4. An adapter whose own `isConfigured()` is false throws `MissingCredentialError`.
- **Destination.** Calls go only to `llmProvider`, never to another provider.

**Contradictions**
1. **Where the mock lives.** `docs/13` §2.2 places it at `test/support/mockLLM.ts` and types it with the old sketch names (`complete`, `LLMRequest`, `LLMResult`). The card says `test/helpers/mockLLM.ts`. I followed the card, and `docs/13` was not edited.
2. **Two estimators in the corpus.** `docs/03` §10.2 has `estimateTokens`: one combined 1.3 ratio for Hangul and CJK, plus 16 tokens of framing. `docs/06` §5.1 has `estTokens` with a separate ratio per script, and its own note says `docs/03` §10.2 "owns the heuristic itself". The card says `docs/06` §5.1, so I followed it. Neither document was changed. The 1.15× safety multiplier is left for the budget step (`P3-T16`).
3. **`src/tts/types.ts` asks this card for one more field.** Its header says the card that creates `src/model/usage.ts` must add `AudioArtifact.usage` back. That file is not in the Files and nothing here needs it, so it was not done.
4. **Files outside the card that had to change.**
   - Replacing the `LLMRouter` placeholder makes `llm: undefined` a type error in `backfill.test.ts`, `searchImport.test.ts`, `searchDialog-flow.spec.ts` and `scripts/bench-search.ts`. Each now gets `mockLLMRouter()`. The integration spec change is one import and one value.
   - For the same reason, `createPipelineContextFactory` now receives the router. That is the "router" part of `P3-T35` step 1, so the `P3-T35` card should drop it.
5. **The card's Verify command finds no tests.** As in `P3-T05`, `"llm/router|tokenEstimate|container"` exits 1 with "No test files found". Separate arguments work.
6. **No document says who enforces the budget.** §4.3 says `LLMCallContext.budget` is "Enforced before the call" but names no enforcer. The router does not enforce it. The mock calls `reserve` before a call and `settle` after one, so the budget-stop scenario can be tested. `P3-T16` should decide where enforcement lives.
7. **The model settings ignore which provider is active.** `summaryModel`, `reportModel` and `screening.model` are not stored per provider (§8.5). After a user switches `llmProvider`, a model id meant for the previous provider is still resolved. This is the §8.5 design and was not changed.
8. **Base URLs that already include a path.** OpenAI's documented base already ends in `/v1`, and `docs/03` §2.1's endpoint table also writes `/v1/...`. OpenRouter is the same with `/api/v1`. The adapter cards (`P3-T07`, `P3-T08`) must join paths to the base without doubling that segment.
9. **The base-URL check is stricter than the card's text.**
   - The card asks only for "non-empty and `https://`". The resolver also refuses a user name, a password, a query or a fragment.
   - It removes a trailing slash instead of refusing the value, even though §8.5 says "no trailing slash". Refusing would send the call to the documented host rather than the gateway the user configured.
   - A refused value is logged once per provider and value. The log names the provider and the reason, never the value.
10. **Stale comment in `container.ts`.** The doc comment on `createPipelineContextFactory` still talks about "seven members". Only the comment next to `llm:` was updated, to keep edits to that shared file small.
11. **A key flag with no adapter is a configuration error.** Until `P3-T07` to `P3-T10` land, a user whose key flag is set for the chosen provider gets `ConfigurationError` ("no adapter registered"), not a missing-key message. This is deliberate: it is a build gap, not a missing credential.
12. **Startup checks only NCBI's key flag against the keystore.** `installSecretStore` reconciles only `ncbi.keyPresent`. The four LLM flags are never checked against the keystore at startup. The adapter cards should make each adapter's `isConfigured()` check the keystore, which is the router's last check before sending.
