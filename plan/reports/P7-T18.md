## How offline is made

The spec turns **Zotero's own switch**, `Services.io.offline`, in the test profile, with
`Services.io.manageOfflineStatus` off for the block, so the operating system cannot turn it back. `Zotero.HTTP` and
the plugin's HTTP client are not replaced (the card's `Do NOT`). Zotero 10's `Zotero.HTTP.request` reads
`browserIsOffline()` before it opens a channel and throws `BrowserOfflineException`. `src/core/http/client.ts` maps
that to `OfflineError` (`rh-error-offline`). Every failure the spec saw from the client was that error.

**Coordinator decision (under item 313; brief: "Never run a keyed or paid path").** The language model is the one
double, as in every model-driven spec of the suite: `registry.get` answers the active provider with a fake, and
`secrets.has` answers `true` for a key that exists nowhere. No key is read or written. While Zotero is offline, the
fake sends its request through the plugin's real client (`graph.http`) to a closed loopback port, so the failure the
pipeline sees comes up from `Zotero.HTTP`. The literature-database adapters are the real ones.

3. **In one summarize window, a second run writes no note.** After a run ends, the window's "write notes" box is
   unchecked and disabled (measured: "checked false, disabled true" at the second Start), so the resumed run stored
   the tenth summary and saved no note for it. The next run, in a new window, wrote it. No data is lost. **Not a card
   under rule 9:** it blocks no finishing condition. Recorded here for `P7-T03`'s window sweep.
4. **`Verify with` cannot run as written.** `zotero-plugin test` 0.9.2 takes no spec filter (its options are
   `--abort-on-fail`, `--exit-on-finish` and `--no-watch`), so `npm run test:integration -- offline` runs the whole
   suite. The spec was run alone during development behind a temporary `.only`, removed before the three runs.
5. **The runner's `debug` lines are lost while offline.** The runner reports over HTTP to its loopback server, and
   Gecko's offline switch refuses loopback too (measured in the first development run). The spec holds lines logged
   offline and sends them once the switch is off.
