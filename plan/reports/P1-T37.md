## What changed

- **`SerializedError` gains two optional members** (`src/core/errors.ts`, and `docs/07` §5.2 in the same change,
  with a dated note saying why):
  - `host`: the failing request's host name only, lower-cased, through `redact`;
  - `timeoutSeconds`: `TimeoutError.timeoutMs` in whole seconds, rounded, at least 1.
  Neither is a `Record`, and `context` itself is not carried (the card's Do NOT).
- **`toSerialized` reads both off public members of one class each**, never off `context`, the way `httpStatus`
  already travels: `host` from a `NetworkError` (so also `OfflineError` and `TimeoutError`), `timeoutSeconds` from
  a `TimeoutError`.
- **`NetworkError` gains `host`** and a constructor with the base's signature, so no thrower changes. It reads
  `context.url` through `hostNameOf`:
  - an absolute URL gives its host name;
  - a bare host name (the pipeline's deadline passes `source.rateLimitKey`, a host) is kept;
  - anything else gives `undefined`: a path, a `file://` URL, a relative URL, an empty string, or a value that is
    not a string.
  The result passes through `redact`, the one redactor, and no new pattern was written. `docs/07` §10.1's copy of
  `NetworkError` and of `toSerialized` carry the same change, with dated notes.
- **The defect the card names is fixed.** `toHierarchy` in `src/core/http/client.ts` now passes
  `redactUrl(error.url)` at the OFFLINE and NETWORK call sites, as `TimeoutError` already did. The HttpError's URL is
  origin plus path (the query is already dropped), so a key in a path segment reached the context before.
- **The view** (`src/ui/viewModels/searchImportViewModel.ts`):
  - `TIMEOUT` and `NETWORK` rows render §8.3's sentences from `host` and `timeoutSeconds`. Both offer Retry, as the
    generic row did from the error's `retryable`. Neither offers Open Preferences: §8.3's "Increase timeout" is
    not drawn, because the message's own next action is to try again (coordinator, item 416(h)).
  - A row's `ref` now receives the whole `SerializedError` rather than the status alone, and returns `undefined`
    when a value its message needs is missing. `errorView` then draws the generic row, so a transport error
    without a host still shows something true (item 416(i)).
  - `UNRENDERABLE_ERROR_ROWS` is empty.
  - `ERROR_DETAIL_FIELDS` is unchanged: the disclosure still shows the code and the status only. Its comment says
    the two new values reach the screen as sentence arguments.
- **Persistence.**
  - `JobRecord.error` passes `redactRecord`, which walks the record and keeps `host` (asserted).
  - `SourceProvenance.error` passes `redactSerializedError`, which copies only the members it names, so it
    carries neither new member. `schema/provenance.schema.json`'s `SerializedError` (with
    `additionalProperties: false`) is unchanged (item 416(g)).
- **The "verbatim" claims** in `src/core/errors.ts`' header (§10.1's hierarchy and §5.2's `SerializedError`) were
  checked and still hold, because `docs/07` was amended in the same change. A dated sentence there says so.

## Tests

The card's negative test is the one that matters. Every value below is planted in the error, and the tests check
where it must not appear.

- **Planted values:**
  - a 32-character hexadecimal key;
  - an OpenRouter-shaped key;
  - query words;
  - a request path;
  - a user path (`C:\Users\planted-user\Zotero\storage\…\paper.pdf`);
  - an export path;
  - a linked audio folder.
- **`test/unit/core/errors.test.ts`**, describe "P1-T37: the host and the seconds, and nothing else of the
  context". It checks that:
  - the projection's member names are a closed whitelist, and none of the planted values is in it;
  - `timeoutSeconds` is 45 for 45 s, 1 for 400 ms, absent on a plain `NetworkError` and absent for a non-finite
    time;
  - a bare host name is kept;
  - there is no host for a path, a `file://` URL, a relative URL, the audio folder, an empty string or a
    non-string, nor on a `RateLimitError` or a `ConfigurationError`;
  - a key-shaped label inside a host name is redacted;
  - persistence: through `redactRecord` the host is kept and nothing planted is; through
    `redactSourceProvenance` nothing planted is, and there is no `host` member.
- **`test/unit/core/http-client.test.ts`**, "redacts a key-shaped path segment out of an offline and a network
  error's context". It checks that:
  - a real offline rejection and a real status-0 resolve, for a URL with a key in its path and its query, give
    errors whose `context.url` holds `[redacted:…]` and neither key;
  - `host` is the host name;
  - the serialized error holds neither key.
- **`test/unit/ui/searchImportViewModel.test.ts`**:
  - `EXPECTED_ROWS` gains the two rows;
  - "UNRENDERABLE_ERROR_ROWS is empty";
  - a transport error without a host falls back to the generic row;
  - the item 230 test now expects the timeout sentence;
  - "draws only the host and the seconds from a real error's planted context": a real `TimeoutError` and
    `NetworkError` with the planted values. The sentence's arguments and the disclosure hold exactly
    `{ host, seconds }` or `{ host }`, and none of the planted values, the path or `/v1/`.
- **Integration** (`test/integration/searchDialog-flow.spec.ts`, section 4b; asserted on the painted text, which is
  the bundle's own):
  - a forced `TimeoutError` for a URL with a planted key in its path and query renders the timeout sentence with
    "eutils.ncbi.nlm.nih.gov" and 45 seconds;
  - a forced `NetworkError` for the same URL renders the network sentence with
    "eutils.ncbi.nlm.nih.gov";
  - both offer Retry and not Open Preferences;
  - the whole error panel, disclosure open, contains no key, no query words, no path segment and no `?`.
