## Coordinator-level decisions

Recorded as "DECIDED 2026-11-02 (coordinator, under plan/00 §6 item 313)" where each applies:
- **Key gate:** `RelatedQuery` has no "keyless" parameter, so the gate is key presence in the adapter. The three calls read the key first and send nothing without one.
- **Strategies:** `"auto"` or no strategy means `"recommendations"`. Other strategies return an empty page, a warning and no request.
- **Rank:** position in the answer. Mapper-dropped rows count; seeds removed from Recommendations do not, so those ranks have no gap.
- **`fromDate`:** applied to the year on our side; undated records stay.
- **Limits and fields:** relation limit clamped to 1000 with no paging. Recommend limit clamped to 500, and above 100 no abstract is requested.
- **Size-cap retry:** one retry at floor(limit/2) with the same fields and a warning. A second refusal propagates. Limit 1 is not retried.
- **Validation:** one `/paper/batch` for all ids. The cap of 15 applies after validation, negatives have no cap, and an id listed both ways stays a positive.
- **All positives failing:** `BadRequestError` 404 with `seedNotIndexed: true` and no POST. The batch's own 400 `No valid paper ids given` is treated the same way. No usable identifier gives an empty page and a warning.
- **Stand-ins:** none for `batch-embedding` or `batch-references`, because neither card reads them.
- **Moved code:** `parseJson` and `throwIfErrorEnvelope` moved to `graph.ts` as `parseSemanticScholarJson`, to avoid an import cycle (Crossref's `parseCrossrefEnvelope` is the precedent).
- **`syntheticReason`:** used as the repo's existing name for the requested `reason`.

No new Fluent or user-visible bundle string was added. Warnings are English on `SourcePage.warnings`, following the P5-T09 precedent, so no Korean draft is needed.

## Contradictions and findings

None of these is blocking.

**1. Stand-ins and policing.** No policing rule refuses stand-ins: `relatedRequests.test.ts`'s "nothing else" check runs only on the sources the agent records, and the walk for `x-api-key` covers `related/`. But P5-T31's "fixture or stand-in" check would pass with no evidence on a scenario that was never recorded, because a stand-in already sits under the key. The note added to P5-T31 tells the owner to read the sidecars.

**2. Validation batch has no scenario.** The plan has no scenario for a validation batch over a `recommend` call's exact ids, and none can exist for every test. So `semanticscholarRecommendations.test.ts` composes that answer from `batch-unresolvable` rows. Only `[SEED, UNKNOWN]+[SECOND]` replays the batch key directly.

**3. arXiv seeds (not fixed).** `toSemanticScholarId` prefers `DOI:`, so an arXiv seed holding a `10.48550/arXiv.*` DataCite DOI goes out as `DOI:`. P2-T05 measured that `/paper/batch` does not resolve those (`SEMANTICSCHOLAR_BATCH_DATACITE_ID`). For `findRelated` this could read as "not indexed", with a 7-day negative cache entry at P5-T12. I suggest preferring `ARXIV:` for those DOIs. This has not been measured on `/references`.

**4. Requested fields with nowhere to go.** `intents` and `isInfluential` are requested, but `RelationEdge` has no member for them, so they are dropped.
