### Contradictions and findings
1. **`docs/05` §7.5 against FR-44:** the sketch filters `type !== "other"`, while FR-44 says "≥5 items" and FR-7 scenario 3 makes an undeterminable paper `other`. Decided for every regular item (item 7 above). The §7.5 sketch itself is unchanged.
2. **The formula is weak on a narrow library.** In a 30-item library that is the collection, a term on every item scores about 0.68 and a term on two thirds about 0.59. Only the check-tag list removes the ubiquitous ones. A test pins this.
3. **The singular keyword `Mouse` gets through.** It scored 0.438 in the measured profile of 39 CRISPR papers against 206, because it is not a check tag. Left as it is.
4. **Bare tags from a translator are not measured.** The note assumes Zotero's PubMed translator saves descriptors as bare tags, which is why the check list covers keywords. `P5-T30` sees this on the owner's library.
5. **`buildProfileStats` is synchronous.** It took 232 to 265 ms in Node on 10 000 synthetic library rows against a 500-item collection, 3 runs, about 13 KB of stored JSON. Inside Zotero's main thread that may be noticeable. `P5-T30` measures it for real.
6. **`membershipHash` covers the source collection only.** A library change does not alter it, so stored weights can go stale while the hash still matches. That follows the card and is noted for `P5-T25`'s cache rule.
7. **Each run makes a second library pass** (`readLibraryTermSources`) beside `buildLibraryIndex`, so two searches per run.
8. **A real bug found and fixed:** `normalizeTitle` decomposes Hangul through NFKD, so title-only keys are recomposed with `normalize("NFC")`.
