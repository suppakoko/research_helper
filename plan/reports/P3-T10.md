**P3-T10 report: Gemini adapter (Interactions API)**

**Verdict.** The card is done at unit level, with two exceptions that `plan/04` §0.2 rule 10 required me to leave alone. The adapter sends `chat()` to `POST /v1beta/interactions` and `listModels()` to `GET /v1beta/models`. The key goes only in `x-goog-api-key`, read from the keystore and wrapped in `Secret`. `expose()` is called exactly once per request. `store: false` is on every Interactions body. Every request carries `mapErrorResponse` → `mapProviderError`, `LLM_ATTEMPT_TIMEOUT_MS` and the call's token, and there is no retry loop. `registerProviders` registers the adapter, so the router reaches it. `listModels()` strips `models/` and drops embedding-only and TTS-only entries. `detectTier()` returns `"free-or-unknown"` on anything inconclusive. The legacy `generateContent` path sits behind one exported function that nothing calls.

The two exceptions:
- **Step 7 (the `HOST_POLICIES` row) is not done.** It depends on P3-T07's unresolved "Open — recommended" line, and rule 10 says to stop at such a step and ask. As a result, production Gemini requests get no rate limiter and make one attempt only, until the row lands.
- **Step 5 is built only to the extent `docs/09` §3.4 rule 4 already decides.** The "ask the user" part of its open line is not built.

Typecheck, `npm run lint:check`, `npx eslint .` and `npm run test` all exit 0. I made no live call and used no real key.

**Assumptions about undocumented shapes** (each is also marked in the code)
1. **Multi-turn input.** When there is more than one non-system message, `input` uses `docs/03` §14.2's sketch shape `{ role, parts: [{ text }] }`, with the role passed through as-is. §4.3 documents only a plain string, which is what a single user message gets.
2. **JSON without a schema.** `responseFormat: json` with no schema is sent as `response_format: { type: "text", mime_type: "application/json" }`. §7.3 shows that object only with a schema.
3. **Status `incomplete`** is read as a truncated answer (`finishReason: "length"`), following the §14.2 sketch.
4. **Other statuses.** Any status other than `completed` or `incomplete` (`failed`, `cancelled`, `budget_exceeded`, `requires_action`, `in_progress`, or missing) becomes a non-retryable `LLMError`, and the content is not read. §4.4 says to "check for completed before reading content".
5. **Interactions safety block: not handled.** It is undocumented, and I invented no shape. A 2xx still goes through `mapProviderError`, which only knows the legacy `promptFeedback.blockReason` and `candidates[].finishReason`. If a block arrives as `status: failed`, the user gets a generic LLM error, not a content-filter error.
6. **Gemini spend cap: not handled.** It is undocumented. A 429 `RESOURCE_EXHAUSTED` stays a retried `RateLimitError`, which is P3-T05's mapping and is tested here.
7. **Model list envelope.** The entries are assumed to be in a top-level `models` array. §9.3 names neither the envelope nor any paging, so no `nextPageToken` is followed.
8. **Model capabilities.** Every listed model is marked `supportsJsonSchema: true` and `supportsStreaming: true`, because §9.3 gives no per-model flags.
9. **Missing limits.** A model entry without numeric `inputTokenLimit` and `outputTokenLimit` is skipped rather than given made-up limits.
10. **Thought tokens.** `total_thought_tokens` is not added to `outputTokens`; §4.4 leaves open whether `total_output_tokens` already includes it. `costUsd` is `undefined`.
11. **Data policy follows the tier.** A tier that is free or unknown gives `trainsOnInputByDefault: "yes"` with 55 days' retention; a paid tier gives `"no"` with 55 days (`docs/09` §3.3).
12. **Temperature and topP.** They are not sent on the Interactions path, because they are not in §4.3's `generation_config` list. `temperature` is sent on the legacy path, which §4.5 documents.
13. **Legacy finish reasons.** Anything other than `STOP` or `MAX_TOKENS` becomes `finishReason: "other"`.
14. **Synthetic test fixtures.** All test bodies are hand-built from `docs/03` §4.4, §9.3 and §11.5 and from `docs/04` §2.4. They are marked synthetic in the test header. None is a recorded fixture; those belong to P3-T30.

**Contradictions**
1. **Step 7 was not executed (rule 10).** The `generativelanguage.googleapis.com` row depends on P3-T07's open line ("the LLM rows in `HOST_POLICIES` carry no fixed request rate…"), which is still open in `plan/04`. Item 259 does not decide it.
   - The recommendation cannot be written as a row as things stand: `RateLimiterConfig.ratePerSecond` is required, and `TokenBucket` throws `RangeError` unless it is a positive finite number. §7.3's LLM/TTS rate cell reads "from provider prefs", but no such preference exists. So any row needs a rate number that no document gives (`plan/README.md` §5 rule 4).
   - **Consequence until the row lands:** in production, Gemini requests have no limiter, and `createRetryFor` makes one attempt, not `LLM_RETRY_BUDGET`. The tests supply the budget directly.
   - **The row ready to apply once decided** is `{ host: GEMINI_HOST, withoutKey: { ratePerSecond: <owner's number>, burst: 1, maxConcurrent: <llm pool size> }, retry: LLM_RETRY_BUDGET }`. `GEMINI_HOST` is exported from the adapter, not from `hostLimiter.ts`.
   - When I finished, no other agent had added an LLM row to `HOST_POLICIES` either.
2. **Step 5's open line.** I built `detectTier` from `docs/09` §3.4 rule 4 only. There is no documented paid signal, so it sends no request, always answers `"free-or-unknown"`, and never infers `"paid"`. Asking the user once per key change, and warning on every job, are the open line's and P3-T15's.
3. **Step 2 cannot be wired.** `docs/07` §4.3's `ChatRequest` has no effort member. `mapEffortToThinkingLevel` is built and tested, but no `thinking_level` is ever sent. Its `Effort` type is a local copy of the `docs/03` §14.1 sketch's union, which is the parallel type `plan/README.md` §5 rule 3 warns against. P3-T08 and P3-T09 have the same gap. The union belongs in `src/llm/types.ts` once doc 07 declares it.
4. **The model filter needed a second rule.** `docs/03` §9.3 says filtering on `generateContent` excludes TTS-only models. But `docs/04` §2.1 and §2.3 show TTS is itself served through `generateContent`, so that filter keeps TTS models. I added `docs/04` §2.2's `/-tts/` id filter.
5. **`isConfigured()` is synchronous; the keystore is asynchronous.** The adapter answers "there is a store, and its last answer about the key was not 'absent'". It asks `has()` once at construction and after `keyChanged()`, and updates on every key read. Until the first answer arrives it does not report the key missing. `chat()` reads the key before every request and throws `MissingCredentialError` with zero requests when it is absent.
6. **`Secret` lives in `src/prefs/secrets.ts`,** but `docs/07` §2.3 says `llm/` imports only `core/` and `model/`. ESLint allows the import, and P3-T01 placed `Secret` there for the adapters to use.
7. **`validateCredentials()` is P3-T14's.** Here it rejects with `ConfigurationError` and sends nothing.
8. **The display name has no string.** `displayNameKey` is `"research-helper-provider-gemini"`, and no bundle carries it. P3-T04 owns the provider-picker strings.
9. **Stale header comment.** `registerProviders.ts`'s header still says "No adapter is registered yet". I left it, because the file is shared.
