## 6. Contradictions with the card or the corpus

1. **`archiveID` version.** `docs/07` §6.2 showed `arXiv:2401.01234` (no version), and `docs/02` §10.3 showed `arXiv:2106.15928`. The card and `docs/02` §7.5 note 4 both keep the version. Both documents now keep the version, with dated notes. Where no arXiv source record contributed (an arXiv id known only from Semantic Scholar), no version is available, and `arXiv:<id>` is written without one.
2. **`issn[1..]` preprint column.** `docs/07` §6.2 said "same", which would write a preprint's second ISSN while dropping its first. The card says to drop ISSN entirely. The column is now "—".
3. **`genre` has no source value.** `docs/02` §10.3 maps the source's first publication type to `genre`, but the work record defined in `docs/07` §5.1 (`CanonicalWork`) carries no publication-type list. The constant `"Preprint"` is written: it is the one value the corpus gives. This is recorded as a new §6.2 row. **The owner should confirm that a constant is acceptable** rather than adding a publication-type member to the work record.
4. **What "type cannot be determined" means.** FR-7 does not define it. `docs/02` §10.2 describes `other` as a classification ("datasets, editorials without a venue"). In the code, every shipped mapper uses `other` only when it could not classify a record (and then lists `type` in `missingFields`), and `merge()` defaults to `other`. This card follows the code and treats `other` as undetermined. The rule is recorded in the §6.2 `type` row.
5. **FR-7 asks for `archiveID` on bioRxiv and medRxiv items too**, but §6.2 maps only the arXiv id to `archiveID`. No value is written for bioRxiv or medRxiv, rather than invent one (rule 4). **This needs a decision.** One candidate is the DOI suffix, which `docs/02` §11.2 calls the stable accession.
6. **Card step 1 names raw source fields** (`bookOrReportDetails.publisher`, `server`). The mappers already copy those into the work record's `containerTitle` and `publisher`, so `detectServer` reads those two, in that order.
7. **The integration test name in the card's Files list** was `preprintRoundTrip.test.ts`. The dated note's `.spec.ts` name was used.
