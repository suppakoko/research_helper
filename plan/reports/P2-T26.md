### Decision (card step 1) and why
`createSourceRegistry` exposed `register`, `get`, `list`, `listConfigured` and nothing else, as measured. `P1-T35`'s Findings say "the interface declares no unregister, so the real PubMed adapter cannot be replaced by a stub" — a statement that there is none, not a reason there should be none; the registry's own header said only "`P1-T07` step 2 … Nothing else" (scope). So the decision was open. An `unregister` was rejected because a removed-then-re-registered adapter moves to the end of `Map` insertion order, and `docs/08` §4.2's checkbox row is rendered from `list()` order; `Map.set` on a present key keeps its slot. The replace also keeps the registry's id set invariant, which is what "do not weaken the duplicate-id check" needs. The reasoning is recorded in the registry header ("Why there is still no `unregister`") so the next reader does not have to rediscover it. "Test-only" is enforced, not asserted: the unit test walks `src/**/*.ts` and fails if any file but `sources/registry.ts` names `replaceForTest`.
