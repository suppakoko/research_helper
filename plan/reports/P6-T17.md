## Decisions taken (each DECIDED 2026-11-17, coordinator, under `plan/00` §6 item 313)

All are in `docs/08` §6.4's note. In short:

1. Both menu entries open the same window. The audio section works on the window's own run's report, else on the
   newest stored one.
2. The audio language is a per-run choice and is never written back. The voice is written back to `tts.voice` at
   once.
3. A refusal before any call is one line, by reason.
4. The report and audio runs exclude each other in the window.
5. The attachment title is localised in Zotero's interface language.

## Findings

1. **The first integration run failed on an older test (fixed, not a card).** `P4-T19`'s "one selector" assertion
   counted every menulist in the report window, and the audio section adds two. The test now leaves out the
   section's menulists and checks the section is hidden while `audio.enabled` is off. The three runs after the fix
   were clean.
2. **Files outside the Files row.**
   - `src/pipeline/audioReport/audioReportPipeline.ts` gained `voices()`, which the window's voice list needs, with
     its test.
   - `test/unit/ui/costConfirmDialog.test.ts` tests the radio group's answer.
3. **Four guards removed as equivalent.** These were the `running` checks on the reason line, the outcome line and
   the two save offers. `audio-started` clears the refusal, the failure, the outcome and the offers, so a running
   state carries none of them. Each line's simplified form was swept again and killed.
4. **The build warns for the pending Korean.** `npx zotero-plugin build` prints "I10N id … missing in locale: ko-KR"
   for the seven ids the window's markup names. This is expected while they are commented drafts (`G-41`).
