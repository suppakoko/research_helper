CONTRADICTIONS/FINDINGS
1. **The open line (followup-292 finding 2).**
   - Settled from the text: an answer with both defects gets one re-run, because both rules' "once" name the same repeated request.
   - Not settled: a second answer showing the other defect.
   - Built provisionally: one shared re-run, so at most 2 `THEME_CLUSTER` requests (`CLUSTER_REQUESTS_MAX`). Missed keys followed by too many themes stops the run; too many themes followed by missed keys sends the leftovers to `Other`.
   - The alternative is one re-run per defect, up to 3 requests. Changing to it means altering one constant and the re-run branch in `clusterThemes`, plus the two "[open line]" tests.
   - **The owner needs to rule on this.**
2. **`Other` can exceed `MAX_THEMES`.** If the model returns exactly `MAX_THEMES` themes and leftovers remain, the result has `MAX_THEMES` + 1 themes. P4-T07 would then make one `CLUSTER_REDUCE` call more than P4-T16 reserved, the same concern as item 292(d). `withBudget` is the backstop. Owner's or P4-T07's call.
3. **`themes` can be empty.** If every theme falls below the minimum, `themes` ends up empty, while `ThemeClustering`'s comment says "At least one". No document says what the run then does (P4-T18 or P4-T07).
4. **English code-side text may reach a Korean report.** `OTHER_THEME_NAME` ("Other" is docs/12's own word), `OTHER_THEME_DEFINITION` and `SMALL_THEME_REASON` are mine. They can reach `CLUSTER_REDUCE` and a Korean report. That is report-language text, which belongs to P4-T12's label table and P4-T21; the definition and reason wording are my drafts.
5. **Bundle choice.** The stop message is in the main-window bundle, per the card's guess: P4-T19's `reportWindow` bundle carries no run messages. P4-T20, which shows run messages in the report window, may want to move it.
6. **Privacy check left to P4-T18.** `cluster.ts` does not call `assertModelAllowed`; it only accepts `routing` hints. P4-T18 must check the strong model against the privacy policy before this stage, as `relevanceScreen` does for its own model.
7. **The output limit must be known.** `outputLimit` must be a positive integer, so for a model whose `ModelInfo` is unknown, P4-T18 must decide what to pass. `planSynthesis` has the same need.
8. **The context window is not checked.** Item 286's trigger is the input budget and output limit only. A model whose context window is smaller than 60 000 plus the ceiling would get `ContextLengthExceededError`; docs/06 §8.4's old "small-context model" trigger was replaced.
9. **The stop is a returned outcome, not a new error class.** This leaves docs/07 §10.1's hierarchy untouched. P4-T18 decides the job's final state.
10. **Pass counting.** `passes` is 1 even after a re-run (step 5: "one pass for the call"). P4-T18's Done-when says "pass count equals the calls made", which holds on clean answers only.
