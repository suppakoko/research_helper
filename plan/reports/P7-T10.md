## Decisions (coordinator, under item 313; `plan/00` §6 item 396(a)–(e))

1. **Which rows each clear removes.** "Cached responses" means every namespace but `summary` and `embedding`.
   "Stored summaries" and "embeddings" also clear their own cache namespace, so a cleared summary is not served
   again from the cache. "Job history" means the jobs that ended.
2. **The pane's "Delete all plugin data" keeps queued, running and paused jobs**; uninstall deletes them all.
3. **Reset keeps 21 state rows**: `secretBackend`, `prefsSchemaVersion`, `cacheLastSeenPromptVersions`, and each
   credential's `…KeyPresent`, `…LastValidatedAt` and `…LastValidationResult`. Resetting them would make the pane
   misreport stored keys.
4. **Uninstall runs keys, then data, then preferences**, each isolated. It opens its own connection, only when the
   file exists.
5. **The confirmation is asked host-side** with `Services.prompt.confirm`, not in the pane script.

## Mutation sweep

Each mutant was planted as a `/* MUTANT` change and the card's tests were run, then the original bytes were restored
and checked byte for byte. **24 of 24 killed** (20 at first, then 4 for `removedCount`):
- response namespaces keep `summary`;
- ended statuses gain `interrupted`;
- `deleteRows` never deletes;
- `clearStoredSummaries` skips the namespace;
- `clearJobHistory` deletes every job;
- `clearEmbeddings` deletes summaries;
- delete-all skips the prune;
- `keepActiveJobs` is ignored;
- report files are not removed;
- delete-all from the pane deletes active jobs;
- reset touches secret rows;
- reset clears `secretBackend`;
- reset clears the key rows;
- a failed key step stops the sweep;
- a data failure is not named;
- the host asks with nothing to remove;
- the host clears after a no;
- an unknown kind is accepted;
- reset runs without asking;
- `bootstrap.js` prints no counts;
- `removedCount` counts cached responses in rows;
- `removedCount` counts "delete all" in rows only;
- `removedCount` counts a table clear in rows plus entries (the old behaviour);
- the host adds rows and entries without `removedCount`.

Not mutated: the `registerUI.ts` wiring and `src/bootstrap/uninstall.ts`'s platform steps. Only the integration spec
covers those.

## Findings (not cards, rule 9)

   that is left to `P7-T03`'s sweep or the owner.
2. **Uninstall in a running Zotero is not measured.** `bootstrap.js` is tested as text against a fake Zotero, as for
   `P3-T02`. `P7-T25`'s manual QA run is where a real uninstall happens.
