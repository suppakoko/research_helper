1. **Which rewrite errors end the run.** They mirror `themeAnalysis.endsStage`: cancel, budget, `AuthenticationError`, configuration, policy, privacy-routing, or anything that is not a `ResearchHelperError`. The failed rewrite's usage is not counted in `CritiqueResult.usage`; the budget guard already holds the spend.
2. **Critique warnings flow through the scaffold.** The scaffold carries them into the report's warnings, so P4-T18 passes them once.
3. **Pass counter definition**, as in reading 4 above.
4. **Synthesis cache placement.** Entries live in the `report` namespace and are gated by `redactRecord`. An unanalysed theme is not cached. `cr` is probed per theme and only the missed themes are sent.
5. **Failure rule** over all papers the report would analyse, stopping at the first failure that crosses 30 %, with one message.
6. **Topic and sources.** The topic is the latest search record's query, else the collection name. `libraryCatalog` is not read.

9. **How a stop is recorded.** The record goes to `failed` with `code: "REPORT_STOPPED"`, `messageKey: "rh-error-llm"` and `detail` = the stop's short name, because the gate's 40-character catch-all redacts the full 42–48-character ids. The window shows the output's `stop`.
10. **Saving cannot be interrupted** once it starts, so nothing half-saved is left.
11. **Restart behaviour.** Resumed jobs run headless, and a pause during such a run is answered "stop". A record of another pipeline, or one with no readable checkpoint, is priced as one call of unknown cost (fail closed).
12. **One language per run.** `auto`/`both` are left to P4-T20/P4-T21.
13. **Report ids** are random UUIDs.

## CONTRADICTIONS/FINDINGS
1. **The redaction gate destroys long message ids in stored records.** The record's gate redacts any run of 40 or more characters, and every `research-helper-report-stopped-*` id is 42–48 characters, so it becomes `[redacted:48]`. I worked around it with `detail` = the stop's short name. Any other code that puts a long Fluent id into `SerializedError` will hit the same thing.
2. **P4-T12 and P4-T14 disagree on the title.** P4-T12's title block has a day-precision date in its `h1`, which never prefixes P4-T14's dated title, so the note would get two headings. I resolved it in the pipeline (`withDatedTitle`).
3. **Partial theme results are lost on a budget pause.** `analyseThemes` throws away the themes already analysed when a budget refusal ends the stage, so "continue" pays for those themes again. Caching each theme as it finishes would fix it inside `themeAnalysis.ts`.
4. **`AnalysedPaper.libraryCatalog` is never filled**, because the summarize Zotero port does not read `libraryCatalog`.
5. **Resumed headless runs have loose ends.**
   - They have no cancel source tied to plugin teardown; disabling the plugin mid-run leaves the run going against a closing database.
   - A job a resume guard paused waits with nothing to resume it until a surface exists (P4-T20 or later).
6. **`REVISION_NOTES_INSTRUCTION` is approved** (item 318(b)), but docs/06 §12.2 reading (8) still calls it "open for approval". I left that for the coordinator.
7. **Concurrent work in the tree:** `plan/08-phase-5-related-papers.md`, `plan/reports/phase5-draft.md`, and coordinator edits to plan/00 (items 318–319) are someone else's (the second agent and the coordinator). I did not touch them.
