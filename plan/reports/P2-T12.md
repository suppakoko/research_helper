# P2-T12 — Batched abstract-backfill pass: report

## 1 Verdict
**Two steps of the three-step backfill ladder now ship. Step 3 (Crossref) is deliberately left out under rule 4.** "Backfill" means filling in abstracts that are still missing after the search; the "ladder" is the order of databases `docs/02` §10.4 says to ask. All four Done-when criteria pass, and so do the card's Verify-with commands, typecheck, both lint commands, the unit, contract and integration suites, and a 15-mutant sweep in which every mutant was caught.

- **Criterion 1 (request budget).** 200 records with 60 missing abstracts cost **1 Europe PMC request and 1 Semantic Scholar batch request**. The limits are at most 2 and at most 1.
- **Criterion 2 (where the abstract came from).** `provenance.fieldOrigin.abstract` names the database that supplied it: `"europepmc"` or `"semanticscholar"`.
- **Criterion 3 (cancel).** Cancelling during the pass ends the run in `cancelled`, not `failed`. The merged works are kept unchanged and nothing is written.
- **Criterion 4 (coverage figure).** The import summary reports the share of created items that have an abstract. That figure, `abstractCoveragePercent`, already existed. It now includes backfilled abstracts (95 % in the 200-record test).
- **Live network requests: 0.** All tests use recorded response files and a fake HTTP client that counts every request.
- **Main design decision.** No interface change was needed. `docs/07` §4.2 already declares `lookup`, an optional batch lookup by identifier. The pass calls that once per ladder step instead of calling `fetchAbstract` once per record.

## 6 Contradictions with the card or the corpus
1. **Card step 4 (Crossref) is not implemented.** The card allows the Crossref step "only if it is a small remainder". Neither `docs/02` §10.4 nor `docs/spikes/phase-0.md` V-13 gives that remainder a number, and Crossref's `/works/{doi}` costs one request per record. Under rule 4 the step was stopped, not guessed. The ladder is `["europepmc","semanticscholar"]`, and both the `backfill.ts` header and the `docs/02` note say why. **The owner's decision is needed:** a number, or dropping the step.
2. **Semantic Scholar requests a wider field list than `fields=abstract,tldr`.** The card's step 3 and §10.4 name that list. The pass instead uses the adapter's existing `lookup`, which requests the adapter's full field list (a superset). The request count and the ~100-id batch size match the document; only the response is larger. If the exact field list matters, the adapter's `lookup` needs a fields option, which would change `docs/07` §4.2.
3. **Europe PMC's 100 DOIs per request is derived, not documented.** It is §10.4's own budget divided out (200 records ÷ 2 calls). Each request asks for up to 1,000 results (§4.1's maximum) so one request holds every hit, and travels by `searchPOST` because 100 DOIs always exceed the 1,500-character design budget.
4. **The card's Files premise was partly wrong.** The note said a batched lookup "is an interface change". It is not: `docs/07` §4.2 already declares `lookup` as a batch lookup. Measured fact: only Semantic Scholar had `lookup` before this card; Europe PMC gains one here.
5. **The import of a preview's works no longer re-runs the pass.** This is a choice made here, recorded in `backfillStage` and in the `docs/02` note: the preview run already asked those DOIs.

## 7 What I did not check
- Real Europe PMC behaviour for a 100-term `DOI:"…" OR …` query sent by `searchPOST`. No recorded response file exists for it; recording one needs a live request.
- Whether the pass should ask only the databases the user ticked. It currently asks the ladder databases from the registry regardless of the selection, because §10.4's ladder is fixed. A user who unticked Semantic Scholar will still see Semantic Scholar requests, and possibly 429 warnings on unkeyed runs.
- Whether `seenIn` should gain the database that supplied the abstract. It does not; only `fieldOrigin.abstract` changes.
- `normalizedAtEpochMs` is not updated when the pass changes a work.
- `estimate()` does not count the pass's requests.
