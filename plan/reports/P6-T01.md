## Decisions taken (each DECIDED 2026-11-16, coordinator, under `plan/00` §6 item 313)

1. **`TTSProvider.maxInputChars` takes the language** (`maxInputChars(language): number`). The card says to keep
   it and `P6-T05` step 5 gives it two values (900 English, 450 Korean characters, `docs/04` §5.2); one number
   cannot hold both. Recorded in `docs/07` §4.4's note.
2. **`TTSProvider.resolveModel(preferredModelId, ctx)` is added.** `P6-T05` step 3 builds it and `P6-T16` step 1
   needs it before pricing; without it on the interface the job would have to reach past the contract.
3. **`AudioAttachmentMode` is `"imported" | "linked"`**, the values `chooseAttachmentMode` already returns
   (`AttachmentMode` in `src/tts/audioStore.ts`), not the card's `"import" | "link"`, so no conversion exists.
4. **`AudioRunOutcome` carries `scriptUsage` beside `usage`** (the TTS calls'), because a stored script makes no
   script call and the two are priced from different tables.
5. **`AudioRunInput.language` is `AudioLanguage | "auto"`**, `"auto"` resolved by `P6-T08`'s
   `resolveAudioLanguage`; `voice` is optional (absent reads `tts.voice`).
6. **The validated script is written to `audioScripts[language]` before the second confirmation**, so a decline,
   a cancel or a TTS failure keeps it (`P6-T16` step 3 already says "written at once"; §12.6 draws it).
7. **The first confirmation is drawn in `Queued`** (before `Scripting`), and skipped with a stored script, so the
   diagram has one `AwaitingConfirm` state — the second confirmation — and `Queued → AwaitingConfirm` for a stored
   script (`plan/09` §0.4 line 13).
