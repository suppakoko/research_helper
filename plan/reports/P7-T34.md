## What was done

1. **`{{TAGS}}` (step 1).** `metadataVariables` in `src/pipeline/summarize/summarizeItem.ts` takes a third argument,
   `sendTags`, which defaults to `false`. Its caller, `summarizeItem`, passes the privacy scope's
   `collectionAndTagNames` (`allowedInputScope` in `src/pipeline/shared/privacyPolicy.ts`). With it, the tags are
   joined as before. Without it, the value is `TAGS_NOT_SUPPLIED` ("not supplied") whether or not the item has a tag.
   No v1.0 control sets the opt-in, so in practice no tag is sent.
2. **Tests (step 2).** Five cases, as above. One test also checks that an untagged item sends the same words as a
   tagged one, so the request does not tell the provider whether an item has tags.
3. **The cache key (step 3).** `{{TAGS}}` is part of the rendered prompt, and so of the summary cache key. A test pins
   that a summary made with the tags is not reused once they are withheld. **Measured:** an untagged item's value
   changed too, from `none` to `not supplied`, so **every** stored summary is made again on its next run, not only the
   tagged ones. Item 395(a)'s record said "tagged items"; this is item 399(a), with the draft answer "keep as built".
4. **Docs.**

## Mutation sweep

A scratch script planted one mutant at a time in `summarizeItem.ts` and ran `vitest` on the card's tests. **6 of 6 killed:**
tags sent whatever the mode; the default sending tags; the condition inverted; an untagged item sending `none` when
withheld; the "not supplied" text changed; sent tags joined with a different separator.
