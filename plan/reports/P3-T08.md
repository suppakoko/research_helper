**P3-T08 report: OpenAI adapter (Responses API)**

**Verdict.** Done at unit level except for step 8. OpenAI now uses the same path as every other provider: the router, the one HTTP client and the one error map. Only the adapter is OpenAI-specific.
- `chat()` sends `POST {base}/responses` and joins the path without doubling `/v1`.
- System content travels as a `role: "system"` entry in `input`.
- `max_output_tokens` is sent and `max_tokens` never is.
- A JSON schema goes to `text.format` with `strict: true`, never to `response_format`.
- Effort is mapped through a function, so `minimal` and `none` become `low`.
- Text is read only from `message` → `output_text` parts, so a reasoning item that comes first is skipped.
- `usage.output_tokens` is taken whole, which counts reasoning tokens as output.
- Truncation (`status: "incomplete"` with reason `max_output_tokens`) becomes `finishReason: "length"`.
- `listModels()` drops embedding, audio, text-to-speech, transcription, image, realtime and moderation entries.
- `countTokens` delegates to `estTokens`.

Every request follows the P3-T38 pattern: `mapErrorResponse` calls `mapProviderError`, `timeoutMs` is `LLM_ATTEMPT_TIMEOUT_MS`, and there is no retry loop. The key is read from the keystore, wrapped in `Secret`, and exposed exactly once. The only header record ever logged has been through `loggableHeaders`.

**Step 8 (the `api.openai.com` row in `HOST_POLICIES`) was not done, on purpose.** The card ties it to P3-T07's line "Open — recommended", which is still unresolved. That line says LLM rows carry no fixed request rate, and §0.2 item 10 says a step that depends on an unresolved open line stops and asks. A row cannot be written without a `ratePerSecond`, and `plan/README.md` §5 rule 4 forbids inventing one. Consequence until the row lands: OpenAI requests get no host limiter, and so no retry budget from `createRetryFor`. Each request makes one attempt. The ready-to-paste row is under Contradictions.

**Contradictions**
1. **Step 8 depends on an unresolved open line.** P3-T07's "Open — recommended" covers the LLM rows' request rate, and §0.2 item 10 says such a step stops. `docs/07` §7.3's LLM/TTS row gives the rate as "from provider prefs", and no such preference exists in §8.5. Once the owner decides, the row is one exact-string insertion into `HOST_POLICIES`, plus a test in `hostLimiter.test.ts`:
   ```
   { host: "api.openai.com", withoutKey: { ratePerSecond: <owner's answer>, burst: 1, maxConcurrent: <owner's answer> }, retry: LLM_RETRY_BUDGET },
   ```
   None of the other three agents had added a row when I last checked `HOST_POLICIES`.
2. **There is no effort input to map.** `docs/07` §4.3's `ChatRequest` has no effort member, and no shared `Effort` type exists in `src/` or `docs/07`. `Effort` is transcribed from `docs/03` §14.1 into `mapper.ts`, and `buildResponsesBody` accepts an optional effort. But `chat()` has nothing to pass, so it never sends `reasoning` and OpenAI uses its default, `medium`. `docs/03` §2.5 recommends `low` for summaries. Adding the field needs a `docs/07` §4.3 decision. P3-T09 and P3-T10 face the same gap.
3. **`ModelInfo` cannot carry "unknown".** It types `contextWindowTokens` and `maxOutputTokens` as plain numbers, but `GET /v1/models` returns IDs only (`docs/03` §9.1), and P3-T13 says to leave unknown fields `undefined`.
   - I used `UNKNOWN_TOKEN_LIMIT = 0` for both limits, and the clamp ignores 0.
   - `supportsJsonSchema` and `supportsStreaming` are `false`, meaning not known.
   - So OpenAI's own catalogue clamps nothing until P3-T13 enriches it.
4. **`isConfigured()` is synchronous, but the keystore is not.** It returns true when a keystore is installed. The key itself is looked up in the keystore by `chat()` and `listModels()` before any request, so a missing key is `MissingCredentialError` with nothing sent (tested). I rejected a cached presence flag, because after a key is entered it would report "absent" for one call.
5. **Fields dropped because `docs/03` records no Responses-API shape for them:** `topP`, `stop` and `seed`. `responseFormat: { kind: "json" }` sends no `text.format`; prompt coercion is P3-T12's. If OpenAI documents these fields, a later card adds them.
6. **The model filter goes one entry beyond `docs/03` §9.1.** §9.1's pattern misses `dall-e-*` image models, so `dall-e` was added to cover the card's "drop … image entries".
7. **The display-name string does not exist yet.** `displayNameKey` is `research-helper-llm-provider-openai`, but no bundle entry was created. Nothing renders a provider name before P3-T04's pane, which adds strings under §0.2 item 1. Creating it now would have meant four agents editing `keys.ts`, both `.ftl` files and `typings/i10n.d.ts` at once. P3-T04 must add it.
