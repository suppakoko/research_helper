## 1. Verdict per item

- **Item 207: fixed.** Unticking every database still writes `sources = ""` to the preference. The search window now reads that empty string back as an empty selection: on reopening, every box is unticked, Search is disabled and FR-2's inline message ("Select at least one database to search.") shows. FR-2 is the requirement that the window offer the seven databases. Only a preference value that cannot be read at all (not a string) still falls back to "all ticked". `docs/07` §8.5 says that being listed in the preference is what enables a source, and `docs/08` §4.2 repeats it, so an empty list means no source is enabled. A dated note was added to `docs/08` §4.2. No preference was added, the `sources` default is unchanged, and `src/bootstrap/registerUI.ts` did not need changing.
- **Item 205: no change in behaviour, as decided.** A dated note in `docs/08` §4.6 says "Open Preferences…" is not always shown, and why. The buttons follow each failed source's own error (item 220's rule), so a run that failed only offline shows Retry alone. `plan/` was not edited.
- **Item 206: done.** Each tier of the duplicate-matching engine (the "dedup tiers") that can produce a flag or a link now has a name: `title-exact`, `title-fuzzy` and `version-link`. The view model resolves each name to text through the window's Fluent formatter (the window's `document.l10n`), and passes that text into the duplicate badge tooltip's `{ $tier }`. The tier id is shown only if no name resolves. The English strings are in the search-window bundle. The Korean entries are commented "NEEDS REVIEW" stubs listed on `KO_PENDING_REVIEW`; nothing was machine-translated. `typings/i10n.d.ts` was regenerated with `npx zotero-plugin build`, with no Zotero running, and gained exactly the three new ids.
- **Item 180: fixed.** `estimate()` no longer charges search requests to sources whose `capabilities.keywordSearch` is `false` (bioRxiv, medRxiv).
- **Item 198, first half: fixed.** `estimate()` now adds the abstract backfill's worst case. The backfill is the pass that fetches missing abstracts, in batches, from Europe PMC and then Semantic Scholar. The worst case is one request per 100 works for each ladder database that is ticked and registered with a `lookup`. The code comment says this is an upper bound, because the backfill only asks about works that have no abstract.
- **Item 198, second half: fixed.** `docs/07` §5.1 defines `normalizedAtEpochMs` as "ms since epoch when this canonical record was last rebuilt". Filling in an abstract rebuilds the record, so a work the backfill changed now gets a clock reading taken once, after the pass's last step. Works the pass did not change keep the time stamp they got when the records were merged.
- **The estimate in the documents:** neither `docs/07` §12.1 nor `docs/08` describes how many requests the estimate counts (§12.1 only names the `Estimating` state), so no note was added to `docs/07`. `docs/07` was not edited.

The linked-version badge's tooltip (`research-helper-search-row-linked`) takes no `{ $tier }`, so the name was declared as asked but nothing shows it.

5. **The old `initialSelection` comment was wrong.** It said a source the preference "does not mention at all starts checked"; the code never did that. The comment now describes what the code does.
6. **Quota row disagreement.** `docs/08` §8.3's quota row offers "Open provider dashboard", while `ERROR_ROWS.QUOTA_EXCEEDED` offers Open Preferences. The item 205 note describes the code. This disagreement existed before this change.
