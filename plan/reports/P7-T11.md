## What was built

- **`src/zotero/notes.ts`, new section 6a.**
  - `pluginContentLibraryIDs()`: the user library and every group.
  - `findAllPluginContent(libraryIDs, audio)`. Without writing, it runs a `Zotero.Search` per library: not deleted,
    item type note, tag contains `RESEARCH_HELPER_TAG`. It then classifies each hit:
    - generated, when it has a tag `isGeneratedTag` accepts;
    - provenance, when it has the bare tag and a title that starts with `PROVENANCE_NOTE_TITLE_PREFIX`;
    - anything else is left alone.

    Audio attachments are found by the library and key that stored reports list, if not in the trash. Each library
    carries its name, whether it is editable, and the folders of its linked audio files.
  - `trashPluginContent(content)`. Editable libraries only. It re-checks each id the way `trashGeneratedNotes` does,
    then calls `Zotero.Items.trashTx` in batches of `PLUGIN_CONTENT_TRASH_BATCH` (100). It never calls `erase` or
    empties the trash.
- **`src/core/dataReset.ts`.** `reportAudioKeys(connection)` reads `audioAttachmentKeys` from every stored report,
  once each, and skips an empty key or a row that does not parse.
- **`src/ui/prefs/preferencesPane.ts`.** Four `PREFERENCES_L10N` ids; `ContentSummary`, `ContentRemovalPort`;
  `contentConfirmLine(summary)`; the host's `removeAllContent(parent)`. The host:
  - finds;
  - asks nothing when nothing was found;
  - asks through the same confirmation port as `P7-T10`;
  - removes exactly the plan it found;
  - logs counts only, never a library name or a folder.
- **`src/bootstrap/registerUI.ts`.** `preferencesContentRemovalPort(graph)`. Its find runs `reportAudioKeys`, then
  `findAllPluginContent`, then `countData("all")`; a library that cannot be edited goes to the summary's skipped
  list. Its remove runs `trashPluginContent`, then `deleteAllPluginData` with active jobs kept.
- **`addon/content/preferences.{xhtml,js}`.** "Remove all Research Helper content…" and its note are in
  `rh-prefs-advanced`, beside the stored-data actions, and share their status line. `removeAllContent` runs through
  `runStoredDataAction`.
- **Bundles and lists.** The 4 en-US strings are in place. The confirmation uses selectors on `libraryCount`,
  `folderCount` and `skippedCount`, so an empty list prints nothing. ko-KR has commented drafts under the marker
  "# Draft (coordinator, 2026-11-17, not adopted; G-41, P7-T11):". The ids are on the lists, and CI `--allow`s them.

## Decisions (coordinator, under item 313; item 396(f))

1. The search finds candidates by the bare tag and classifies them; it does not search by each generated tag.
2. The stored rows are deleted with active jobs kept, as the pane's "Delete all plugin data" does.
3. The integration spec trashes only the items it made and restores them. It does not run `deleteAllPluginData` on
   the shared test profile, because other specs' rows live there.

## Mutation sweep

and checked byte for byte. **6 of 6 killed:**

integration spec covers them, and a mutation round over Zotero runs was not made. Stated here as the sweep's limit.
