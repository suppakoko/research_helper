## What was built

- **`.github/workflows/release.yml`** (rewritten) has two jobs.
  - **`build`** runs with `contents: read` and checks out with `persist-credentials: false`. Its steps, in order:
    1. `npm ci`.
    2. The tag and `package.json` must name the same version.
    3. Lint and typecheck.
    4. `npm test`.
    5. `npm run l10n:check`.
    6. `npm audit --omit=dev --audit-level=high`.
    7. `npm run build`.
    8. Collect the release files: the XPI, the update manifests and `SHA256SUMS.txt`.
    9. **Check the built manifests** (a short inline Node script):
       - the built `manifest.json` must name the tag's version;
       - exactly one XPI must exist;
       - the expected update manifest must exist;
       - every `update*.json` entry for this version must carry a `sha512:` hash of 128 hex digits, equal to this
         run's own SHA-512 of the XPI.
    10. Upload the files as a workflow artifact.
  - **`publish`** (`needs: build`) alone holds `contents: write`. It downloads the files, creates the GitHub Release
    and, for a stable release, commits `update.json` and `update-beta.json` to the `release` branch, as before.
  - The workflow level grants nothing (`permissions: {}`).
  - `FIXTURE_MODE: replay` is removed.
  - The tag reaches every shell script through `env:`, never as `${{ }}` inside `run:`.
  - Every `uses:` is pinned to a 40-hex commit, with its tag as a comment.
  - The header comment records each change and its source.
- **`package.json` / `package-lock.json`.** `zotero-plugin-toolkit` changed from `^5.2.0` to `5.2.0` in
  `package.json` and in the lockfile's root entry, both edited by hand. The lockfile's `node_modules` entry already
  resolved 5.2.0. No `npm install` was run.
- **`test/unit/scripts/releaseWorkflow.test.ts`** (new). It reads the workflow files as text, with no YAML
  dependency, and asserts:
  - **Every file the test covers** (`release.yml` and `compat.yml`):
    - every `uses:` is `owner/repo@<40 hex> # vN`;
    - no `FIXTURE_MODE` and no `secrets.` in code lines;
    - `permissions: {}` at the top, and permissions named in every job;
    - no `${{` inside a `run: |` script.
  - **`release.yml`:**
    - `npm ci` comes before `npm test`, and the tests, the l10n check and the audit all come before the build;
    - no `npm install`;
