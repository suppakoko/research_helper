## The five red tests — cause and fix, one by one
Typecheck showed 3 errors when I measured, not 7. They were `TS18047 'sparse'` and the two `TS7006` errors. Both were test typing defects: `mapPaper` returns `null` while `must()` checks only for `undefined` (fixed with `?? undefined`), and two reporter parameters lacked types (now typed).

1. **"reports key presence through the store's cheap has()…"** — the test was wrong. `fakeSecrets(value = PLACEHOLDER_KEY)` used a default parameter, and JavaScript applies a default to an explicitly passed `undefined`. So `fakeSecrets(undefined)` built a keyed store. The helper now decides from `args.length`, so `fakeSecrets(undefined)` is a store with no key. Assertions unchanged.
2. **"sends no x-api-key when the store holds no key, or an empty one"** — the test was wrong, same cause and same fix. Assertions unchanged.
3. **"searchByRelevance sends plain text… names the dropped NOT term"** — the code was wrong. The recorded fixtures show the bulk endpoint ignores `limit` (27 records for limit 1 and for limit 3; 1000 records unwindowed). So comparing a page's length with the limit sent says nothing about whether more exist. `docs/07` §4.2 says `nextCursor` undefined means "no more pages", and `docs/02` §6.6 says pagination is by token. The short-page rule (copied from Crossref and Europe PMC) would silently drop the remaining records of a short page that carries a continuation. Same reasoning for relevance `next`. Removing the rule makes two inherited green tests encode the wrong rule, and I rewrote them:
   - "continues on a fresh token, a short page included; stops on no token, a repeated token or an empty page"
   - "follows the server's token past a short page; stops on an empty page, a repeated token or no token"

   Their assertions are inverted, not weakened, and each stop condition is still asserted.
4. **"pages by token until limit…"** — the code was wrong, same cause and fix as item 3.
5. **"record-rich: … Geneformer paper…"** — the test was wrong. `docs/02` §10.2 maps `subjects` from both `fieldsOfStudy` and `s2FieldsOfStudy`. The recorded paper carries Medicine in the first and Medicine, Computer Science and Biology in the second. The expectation now lists all three, in mapper order.

## Contradictions with the card or corpus
- **The brief says no other agent was in the tree.** That was false from about 16:36 (see Verdict). The other card also edits `scripts/record-fixtures.ts`, which is in `P2-T05`'s Files, and `P2-T36` depends on `P2-T05`.
- **The brief lists 7 typecheck errors; I measured 3.**
- **Card step 3 says build `isConfigured()` from key presence.** The adapter returns `true`, with key presence reported by `hasApiKey()` instead. `docs/07` §4.2 defines `isConfigured` as "e.g. required key present", the key is optional, and `listConfigured()` would otherwise hide the source from every unkeyed user. I kept this.
- **Card step 4 asks for a localized "add a key" message.** `SEMANTICSCHOLAR_UNKEYED_NOTE` is English. No Fluent id exists, and `sources/` may not import `i18n/`.
- **`openAccessPdf.disclaimer`**: `docs/02` §10.2 and §6.10 say to keep it, but `docs/07` §5.1 `OpenAccessInfo` has no slot for it. Not mapped.
- **The `tldr` row**: `docs/02` §10.2 still has a `tldr` row, while §10.4 removed it and `CanonicalWork` has no field. The mapper uses `tldr` only as the abstract fallback.
- **The recorder's pattern exemption.** `docs/13`'s recorder rule says pagination tokens are exempt "by name, per source … and nothing else". `semanticscholarOpaqueTokens` in `scripts/record-fixtures.ts` exempts every 40-hex run in a body by pattern, and the sidecars call paper ids "pagination tokens". The exempted runs also skip the environment-secret deny-list. I did not tighten it because the other agent was editing that file.
- **`P1-T44` duplicates the health check.** `src/ui/prefs/preferencesPane.ts` duplicates the `docs/09` §2.3 test call that the adapter's `healthCheck` now implements.
