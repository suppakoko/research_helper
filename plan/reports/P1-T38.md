## Where the card's text is stale (followed the code, recorded here)

1. **Five validation ids, not four.** `SEARCH_IMPORT_VALIDATION_KEYS` in
   `src/pipeline/searchImport/searchImportPipeline.ts` now has five: `emptyQuery`, `noSources`, `limitOutOfRange`,
   `noTarget` and `worksMisaligned`. The fifth was added by `P2-T31` (the import's works must match the preview's).
   No window can trigger it: the view model always passes the preview's own works back (`runImport`). So no
   sentence was written for it, and the card's "Do not invent a fourth validation message" is kept.
   `VALIDATION_HEADLINES` leaves it out, and a run rejected with it keeps the earlier headline
   (`rh-error-configuration`).
2. **"No import target" cannot be reached from the Search button, or the Import button.** The pipeline checks the
   target only on an import. Since `plan/00` §6 item 358(b), the window's Import button asks for a collection
   name when "New collection…" is chosen, and a dismissed prompt imports nothing. And `runImport` in the view model
   refuses an unnamed target before the pipeline is called. So `research-helper-search-target-missing` is shown at
   that refusal, as an inline warning banner (`role="alert"`) above the kept preview. The spec drives it from the
   window's host API, which is the only way to send an unnamed target.
3. **Files.** Besides the card's six files, the change touches:
   - `addon/locale/ko-KR/research-helper-searchDialog.ftl`: a comment only, naming the three pending ids; no Korean;
   - `.github/workflows/ci.yml`: the l10n step's `--allow` for the three ids, the pattern that step's own comment

## Tests

- **Integration** (`test/integration/searchDialog-flow.spec.ts`, the `P1-T22` block). The old test "does not blame
  the network for an empty keyword" was replaced by three tests, sharing a helper, `assertRejectedHeadline`. The
  helper checks that:
  - the panel is the error panel and no source was asked;
  - the headline points at the expected id (`pointedAt`);
  - it renders the bundle's own text for it (`resolved`, then `rendered`). `rendered` waits for that text in the
    element, so an empty element times out rather than passing, which is the failure `P1-T22` measured;
  - the headline is not empty, does not say "Could not reach any database", and neither button is shown.

  The three tests:
  - **empty keyword**: started with `controller.search()`, the method the Search button calls; the headline names
    the keyword;
  - **out-of-range Max per database**: the box set to ten times the maximum; the headline names both ends of the
    range;
  - **no collection**: `runImport` driven with `collectionID: "new"` and no name. No job starts, the banner renders
    the sentence with `role="alert"`, and the preview's rows are all still there.
- **Unit** (`test/unit/ui/searchImportViewModel.test.ts`, describe "P1-T38 — validationHeadline()"; 3 tests):
  - `VALIDATION_HEADLINES` holds exactly the pipeline's validation ids less `worksMisaligned`, each answers with
    its own id, and `worksMisaligned` gets none;
  - the range sentence carries `PREFS.maxResults`' `min` and `max`;
  - only a `CONFIGURATION` error is answered, and an inherited name such as `toString` is not.
- **The markup link, measured in Zotero:** every other test in the block that renders a `mainWindow.ftl` string
  (the OFFLINE row, the 429 row, the database names on the checkboxes, the import summary) passed with the
  run-time call removed, in every run below.
