## Findings

1. **A copy of `lookupThroughCache`.** Fill-in holds a private copy in `recommendPipeline.ts`, because `related/generators.ts` is outside the Files list. A test holds both to one cache, so they cannot drift apart unnoticed on the cache side.
2. **A limit on the egress log.** A transport failure or a cancel while the model call is in flight leaves no log entry, because `runProfileCall` returns `egress` only on an answer or a fallback.
3. **A display string not built.** `RECOMMEND_DISPLAY_NAME_KEY` names `research-helper-menu-collection-recommend`, whose string is `P5-T26`'s to add.
4. **`planRelatedSeeds` still has no caller.** This card does not use it.
5. **A rebuild on each keyed run for one kind of collection.** When no member has a vector, the profile has no `embeddingModel`, so `isFresh` is false on each keyed run. The run rebuilds and says `profileRebuilt: true`, and pays nothing because the answer is cached. `P5-T30` and `P5-T31` should read this on real data.
6. **`ProfileCallSurface` needs a guard against a second question.** `runProfileCall` confirms again when it is called again after a pause. `profileCallWithPauses` answers the second `confirm` itself once the user has said yes.
7. **A lookup answer can move a candidate out of the date window.** With stand-ins, a lookup record with a matching DOI and the year 1999 merged into its candidate. The merged date then made `contentFilters` drop it as `outside-window`. This follows from the merge rules and is not a fault in this card, but `P5-T31` should watch for it on real answers.

None of these blocks a phase's finishing conditions, so none is proposed as a card.
