## 6. Contradictions with the card or the corpus

1. The Files list still says `create test/unit/ui/searchImportViewModel.test.ts`. The file exists and was modified, as the rule-10 note says.
2. The Verify-with `diff` cannot pass under the project's Korean convention: commented stubs, `KO_PENDING_REVIEW`, gate G-41, and "nothing machine-translated". It already failed at `86fc7a0`. No Korean was written.
3. **Row 142 was a real defect.** The `P1-T20` design put a `data-l10n-id` on each XUL checkbox, with a value-only message. Fluent writes a value into the element's text, which wipes the checkbox's own label and check box. The earlier unit test asserted the id rather than the painted label. The fix sets the resolved name as `label`, and falls back to the source id if the name does not resolve.
4. **The pipeline and the window disagree on "all failed".**
   - The pipeline's `fetchStateFromReports` (in `stages.ts`, not edited) calls a run `"partial"` when every searching source failed, because bioRxiv and medRxiv make no request and so cannot fail. With the default seven ticked, the all-failed panel was therefore unreachable.
   - The view model now decides this through the capability (`everySearchFailed`). The pipeline outcome, the provenance record and the progress popup still say "partial"/"succeeded".
5. **Step 5 says "an Open Preferences… button".** The button still follows `docs/08` §8.3's action for each error kind, as `P1-T22` decided. It appears when any failed row's action is Open Preferences. An offline-only failure shows Retry alone, which an existing integration test requires. Whether the button should always show needs an owner decision.
6. The duplicate tooltip names the matching tier by its identifier (for example `title-fuzzy`), because no bundle has a tier vocabulary. This is the same gap as the Type column.
7. Writing the `sources` preference (step 1) needed a new port, `saveSources`; `docs/07` §8.5 names these checkboxes as the preference's only control. Unticking everything writes `""`, which the window reads back on the next open as "all ticked".
