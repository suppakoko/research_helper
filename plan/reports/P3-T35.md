CONTRADICTIONS/FINDINGS
1. The router is budgeted, but only for callers that pass `budget: ctx.budget`. docs/07 §4.5 (item 248) says every job carries "that same router" instance, and router.test.ts asserts that identity. So I wrapped the one router once with withBudget, and did not bind each job's guard into a per-job router. As a result, an LLM call made without `budget: ctx.budget` is not budgeted. P3-T29 must pass it on every call; the docs/07 note says so.
2. Reservations are priced from the documented table only. pricesFor is synchronous, and the model catalogue is asynchronous and not in the service graph (P3-T14 builds one inside registerUI for the pane only). So the live catalogue's prices and the user's price table (`user_price`) do not reach the reservation estimate. A user price above the documented one would let a call reserve less than the dialog showed.
3. A settled call is priced at its reservation unless the provider reports a cost. The per-job guard is built without `prices`, because one guard serves several models (screening and summary). A call whose provider does not report costUsd therefore settles at its reservation estimate (with headroom and the full maxOutputTokens), marked estimated. This over-counts, which is the safe direction, but the Usage readout will say "estimates" for non-OpenRouter providers. Fixing it means making the reservation carry the request's own prices (budget.ts, outside Files).
4. Seams left for P3-T29, none faked:
   - pass `remaining` to `createSpendResumeGuards` in installServices step 8;
   - build the JobNotifier;
   - give createSkipCachedGuard its probe;
   - call `confirmRunCost`;
   - open collection jobs with `openJob({ record, collection })`, never `forJob`;
   - flush `job.checkpoints` when a job stops, and pass the writer as runPooledItems' `checkpoint` sink;
   - pass `budgetStopOf` (followups-273-274 finding 3).
   Automatic resume stays off until then (item 250).
5. forJob's privacy is now the global mode, no longer strict. That is loadPrivacyPolicy's own rule for a job with no collection. The docs and the doc comment say a collection job must use openJob. No shipped pipeline reads `privacy`.
6. collection_settings is built in container.ts over `database.ready`, not inside installPluginDatabase, because pluginDatabase.ts is not this card's file. It adds no connection and no teardown of its own.
7. These comments are now slightly stale, in files outside Files, and were left alone:
