## CONTRADICTIONS/FINDINGS
1. **FINDING P4-T22-1 (blocks the finishing condition).**
   - The card's "32 000 (forcing two-stage clustering and sub-batching)" and `plan/07` `P4-T05`'s "`P4-T22` forces the path with a small simulated window" both assume the window drives the path. It does not. Two-stage comes only from the output limit, and `ClusterInput.inputBudget` has no caller outside tests. `plan/reports/P4-T06.md` finding 5 already flagged this as an open hook. P4-T18 did not wire it, and no card owned it.
   - Real case: `parseCatalogueEntry` (OpenRouter) gives a model with no stated completion limit its whole window as its output limit, so such a model gets the 52 000-token clustering request in one call.
2. **A refusal degrades quietly before it fails.** `endsStage` in `themeAnalysis.ts` treats `ContextLengthExceededError` as one theme's failure. On the 32 000 run ten requests were refused and no merge was ever sent, so every split theme ended unanalysed before the report call failed. If the report call had fitted, a report missing most themes would have shipped. The fix removes the trigger, but the behaviour stands for a window the budgets misjudge.
3. **A request can ask for more than the model's limit.** `TREND_REPORT_EN` asks 23 000 on an 8 192-output model. `docs/12` §10 records that the OpenAI, Anthropic and OpenRouter adapters clamp this and the Gemini adapter does not. The mock bypasses adapters, so this is not enforced. On such a model the clamped ceiling is well under the 19 722 tokens (visible text plus reasoning allowance) `docs/12` §10's derivation sizes a 4 250-word report for, so a real run may truncate. Recorded only (rule 9).
4. **The estimate says two stages at 400 papers even when the run takes one.** `twoStageClustering` is true on the 128 000 run because `planSynthesis` assumes 140 × 1.15 tokens per digest, against the 52 427 measured. Over-reserving is the safe direction, but `ClusterInput.outputLimit`'s comment says "the run and its estimate choose the same path", which is not always so. Recorded only.
5. **`report_notable_papers_invalid` appears on every run.** This comes from the scripted report, which writes no Notable Papers table, and is not a pipeline defect. `report_digests_trimmed` on the fixed 32 000 run is the intended behaviour.
6. **The card's pointers are out of date.** "`P3-T25` (NOT BUILT)" and the `Files` caller are stale; the type exists and I used it. `plan/00` §6 item 325's "unit tests only" was followed.
