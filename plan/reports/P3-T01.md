**Contradictions with the card**
1. "Verify with" line 1: `npm run test:unit -- "secrets|errors"` exits 1 with "No test files found", because Vitest treats a filter as a substring. The working form is `-- secrets errors`.
2. "Do" step 1 says the standard to-string tag returns `[Secret]`. `docs/09` §2.1, which the same step says to follow exactly, prints a getter returning `"Secret"`, which gives `[object Secret]`. I followed `docs/09`.
3. "Do NOT" forbids giving `Secret` a getter, but `docs/09`'s class has one: the getter for the to-string tag. It returns a constant, never the value, so I kept it, reading the rule as "no getter for the value". The prototype-members test asserts that no member except `expose()` returns key material.
4. The lint rule as specified (an object literal passed directly to `Zotero.HTTP.request`) does not reach the plugin's one real call site. `createZoteroHttpTransport` in `src/zotero/zoteroApi.ts` stores `Zotero.HTTP` in a local variable and calls `request` on it, passing an options object built in `src/core/http/client.ts`. That path is closed by the type system instead: `HttpTransportOptions` declares no `debug` member. The comment on `FORBID_HTTP_DEBUG` says so. I did not widen the rule.
5. The card says its claim about a second block was "Unverified by running it". Run 11 has now verified it: a later block replaces the array and drops the registration selectors.
6. Callers rule (`plan/README.md` §5 rule 10): `loggableHeaders` and `Secret` both ship with no caller. That is what the card intends, since step 3 adds no call because the client logs no header, and the adapters come later.
