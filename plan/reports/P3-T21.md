   It is followed by "> **Measured 2026-10-23 on Zotero 10.0.3 (`P3-T21`, …synthetic two-page PDFs…; no publisher file).**", which has seven points:
   - (1) Read from 10.0.3's omni.ja: openStructuredDocumentTextPack takes an ArrayBuffer, a Uint8Array or a byte source { byteLength, read(offset, length) }. Its reader methods are listed, and the module also exports getLogicalBlockText.
   - (2) The plugin sandbox has no `require`; loadSubScript(url, { module, exports }) on structured-document-text.js and pako.js works.
   - (3) The decoded document's keys are exactly catalog, content, metadata, schemaVersion. Schema 1.2.0, pack version 1, processor pdf version 14. catalog is { outline, pages }; a page is { viewRect, contentRange, label }.
   - (4) An outline entry is { title, ref }, where ref[0] is the top-level block index; children appear only on nested entries. Native entries carry source "native"; inferred entries carry no source. A bookmarked file's outline held the inferred title entry plus 5 native entries, and every native entry was anchored to its heading block although each /Dest points at the top of its page.
   - (5) The block and text-node shapes. Heading text nodes carry style.bold, which nothing reads.
   - (6) Worker plus decode took 20–67 ms per two-page file (12 timings over 4 runs).
   - (7) getFullText put each block of these files on its own line, unlike P3-T18's pages.
   It ends with what none of this measures.
2. §3.6, after the AcquiredSource block:

Sections cover the **body** only: the abstract preamble is the `abstract` field, not a section, and is never counted towards the two."
3. §4.3, after the "fewer than two" paragraph:
   "> **Decided 2026-10-23 (owner, `plan/00` §6 item 271(c)).** The Tier 2 detector above is **not** a line scan first. Heading *positions* come from `getStructuredDocumentText`'s section outline (`catalog.outline`) and its classified `heading` blocks (§3.3.5); the table above then **labels** each of those headings by its text, top to bottom, first match wins, exactly as written. The line scan with the table (the "< 90 characters … no terminal period" rule) runs **only as the fallback** for headings the outline does not anchor, and nothing keys on `style.bold` (`V-8b`: not portable). The "fewer than two → `sectionAware: false`" rule is unchanged, and so is Tier 3: `@sec-type` first, then the table on the section's title."
4. §4.3, the next note: "> **As built 2026-10-23 (`P3-T21`, `src/pipeline/summarize/imrad.ts`) — readings the rules above leave open.**" It has six points:
   - (1) Which structure headings count. Labelled outline entries and labelled heading blocks are kept. An unlabelled outline entry is kept only at the "section level", meaning the shallowest outline depth that holds a labelled entry, so "Acknowledgements" ends the Discussion while "2.1 Cell culture" stays inside the Methods. Unlabelled heading blocks are ignored.
   - (2) How a heading is found in the flat text: its words as whole words, any whitespace run standing for a space, inside its own page, never before the previous heading, preferring a match at the start of a line. A heading that cannot be found is dropped.
   - (3) The fallback adds only a label set that no found outline heading already carries. With no structure at all, the scan is the whole detector.
   - (4) The gate counts distinct label sets, and below two the detector returns no sections at all.
   - (5) A compound @sec-type is split on "|". supplementary-material sections never arrive, because extractJats drops them.
   - (6) The structure is read once per Tier 2 acquisition, after cleaning, and never for a truncated text.

CONTRADICTIONS/FINDINGS
1. AcquiredSource is declared in src/model/summary.ts, which the card's Files list leaves out, but step 4 requires a flag on it. I edited the file and recorded the change in docs/06 §3.6. docs/07 does not declare AcquiredSource.
2. docs/06 §3.6's section type cannot mark one section as both results and discussion, which Done-when line 2 requires, and it has no offsets, which Done-when line 1 ("at the right offsets") and P3-T22 need. I added labels, start and end, and kept imrad as labels[0].
3. Cost. Every Tier 2 acquisition now makes one extra PDFWorker job, getStructuredDocumentText, which lays out every page. It costs about 20–67 ms on a two-page file; the cost on long papers is unmeasured. It is skipped when D-06-3 truncated the text. P3-T22 may want to measure the cost on the G-12 corpus, or skip the read while IMRAD_DETECTOR_VALIDATED is false.
4. The alternative not taken: Zotero.SDT.getReader. It would cache the pack and make repeat reads free, but it writes a .zotero-sdt-cache file into the attachment's folder, so I chose the direct call that writes nothing. That choice belongs to the owner if the cost matters.
5. A stale comment outside my files: src/pipeline/summarize/jats.ts's module header still says "`AcquiredSource.sections` stays empty until then". Reported here, not fixed.
6. On these synthetic files the worker classified the paper title as a heading and put it in the inferred outline. It becomes an unlabelled "other" boundary at offset 0, which is harmless. P0-T18 saw the same on real files.
7. §4.3's table does not match Roman-numeral or decimal-subsection numbering ("II. METHODS", "2.1 Methods"). I did not widen it, because the card says to apply the table as written. P3-T22 will show whether this matters.
