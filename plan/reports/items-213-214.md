# Items 213 and 214: translator timeout default and the PMCID route through the NCBI ID Converter

## 1. Verdict

**Both items are done.** Every check passed, and no live requests were sent (**0**).

**Item 213, the translator timeout.**
- The per-record lookup through Zotero's own translators now has a 30-second deadline by default. When it runs out, that record is hand-mapped instead. Hand-mapping (also called Strategy A) means building the Zotero item from the search result's own fields.
- The writer applies the default when it builds the options for translator import (also called Strategy B).
- The shipped code does **not** cancel a lookup that times out. It only stops waiting for it. The rest of the code ignores the late result: the item is never counted, repaired or returned.
- **However, Zotero's `translate()` saves its item into the collection by itself.** A late lookup therefore still saves a second copy next to the hand-mapped one. This was measured inside Zotero 10.0.3: 1 item when the import returned, 2 items after the late lookup finished. Per the brief, this is reported, not fixed (section 6, item 2).

**Item 214, the PMCID route.**
- A record whose only identifier is a PMCID (a PubMed Central number) is now resolved to a DOI or a PMID through the NCBI ID Converter before the translator lookup.
- The converter sends up to 100 ids per request. It goes through the shipped HTTP client, so the rate limiter, the User-Agent header and the error redaction all apply.
- It never sends an API key.
- A PMCID the converter cannot resolve is hand-mapped without a lookup. The same happens when the converter's answer cannot be read.
- Its host, `pmc.ncbi.nlm.nih.gov`, has its own rate-limit row. The row was added to `docs/07` §7.3 first, then copied into the code.

**Where the converter lives:** `src/sources/pubmed/idConverter.ts`. A path `src/pubmed/` does not exist. During the session a mutation marker sat briefly in `src/sources/pubmed/idConverter.ts`. The final `grep -rn MUTANT src test addon typings scripts` finds nothing (grep exit 1).

## 6. Contradictions

1. **Batch size.** `docs/02` §3.7 gives 200 ids per request as "documented historically", then says to "re-confirm before relying on >100". 100 was chosen as the largest batch the document supports without that re-confirmation.
2. **"30 seconds per record" against PMID batches.** P2-T18 built a group of up to 200 PMIDs (PubMed numbers) as one lookup with one deadline. With 30 s now set, a slow batch falls back entirely as `timeout`, and its late answer can then save up to 200 duplicate items. `docs/07` §12.1 states the shipped behaviour and marks the question open.
3. **The late save cannot be stopped by this code.** `withDeadline` stops waiting but cannot cancel `translate()`, which saves into the collection itself. Whether to accept, detect or remove the late copy is an owner decision.
4. **`docs/02` §3.7 does not show an unresolved record.** The test body for that case is synthetic and marked as such.
5. **`docs/02` §2.2's contact-parameter table names "NCBI E-utilities" only.** The converter follows §3.7's example, sending `tool=research_helper` and `email=` the maintainer address. The client's guard on those parameters (`assertContactPolicy` in `src/core/http/client.ts`) checks only `eutils.ncbi.nlm.nih.gov`, so the converter's address is held only by its own tests.
6. **Two NCBI hosts, two buckets.** The E-utilities host and the converter host each allow 2.5 requests per second, so together they could reach 5 requests per second from one address. NCBI's "three requests per second" guidance may count all NCBI hosts together. The dated §7.3 note says this.
7. **Retries.** The shipped HTTP client receives no retry policy (`container.ts` does not supply `retryFor`). The new row's retry cells, like every other row's, are therefore not used: the converter makes one attempt.
8. **Missing suite-wide translator stub.** `plan/00` item 208 describes a stub of `Zotero.Translate.Search` for the whole integration suite. It is not in the tree: no file under `test/` outside `translatorImport.spec.ts` names `Translate`.
9. **`docs/02` §2.4's copy of the rate table** (marked "NOT AUTHORITATIVE") does not have the new row. It was not edited.
