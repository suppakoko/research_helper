## 6. Contradictions with the card or corpus

1. **Criterion 4 vs gate G-41.** Criterion 4 wants the string "present in both en-US and ko-KR". The corpus has no Korean wording for it, and G-41 forbids machine translation. ko-KR has a commented stub, and the id is on `KO_PENDING_REVIEW`. **The owner (or gate G-41) must supply the Korean.**
2. **The card's Read-first cites `docs/07` §6.5 for "how related items are recorded".** §6.5 covers trend-report notes. No section of `docs/07` described related items, so the rows were added to §6.2.
3. **Do step 1 names signals that cannot be harvested:**
   - "a shared S2 `paperId`": `ExternalIds` has no paper id (`docs/02` §11.3 note).
   - "`is-published-in`": not in any recorded Crossref fixture; only `is-preprint-of` and `has-preprint` occur.
   - `<arxiv:journal_ref>`: text only, so it is deliberately not harvested.
4. **`docs/02` §11.4's "suppress the preprint" default is superseded by G-16.** A note in §11.4 now says so.
5. **Design choices the card leaves open, recorded in `docs/07` §6.2:**
   - A relation is written only between items created in the same import. An existing library item is never modified, per P1-T14.
   - The superseded tag also goes on a preprint imported alone when its published DOI is known. `docs/10` §5 question 2 says "when a DOI match is found".

## 7. What I did not check

- How often real Semantic Scholar records carry both the journal DOI and the arXiv id.
- Behaviour with more than two versions of one work, for example a bioRxiv preprint, an arXiv preprint and a journal version together.
- A preprint whose only published-version identifier is a PMID or a Europe PMC id: it gets no `extra` line by design, but this was not tested in Zotero.
- Whether reading a saved item back into a work (the existing read-back function `fromZoteroItem`) recovers `relatedVersionIds` from the `Published DOI:` line. It does not; nothing reads those lines back.
- The main-thread time of `versionAwareBatches`; its pairwise comparison is cheap only because few works carry `relatedVersionIds`.
- Concurrency: my `npx zotero-plugin build` after M14a ran at about the moment the P2-T14 agent's integration run started at 22:59:44. Neither agent's later runs showed a problem.
