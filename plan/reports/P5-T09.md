## CONTRADICTIONS/FINDINGS

1. **A reference's record makes the merged work's type "other", even after it is filled in.** Measured with the scratch script against the shipped `dedupeAndMerge`:
   - A minimal record plus a `journal-article` from Europe PMC with the same DOI gives one work with the real title and authors, but `type` `"other"`.
   - The cause is that `merge` reads `type` through `pickFirst` with `DEFAULT_PRECEDENCE`, and Crossref leads it.
   - No type this adapter could write is safe, because whichever one it writes wins.
   - **Recommended:** in `src/model/merge.ts`, treat `"other"` as absent when reading `type`; the existing `type?.value ?? "other"` already covers the fallback. Add that file to `P5-T12`'s Files. I did not run this change against the merge tests. `merge.ts` is outside my Files, so I did not touch it.

   - A DOI that Europe PMC does not hold therefore stays a row with a DOI and an empty title.
   - **Recommended:** a Crossref `lookup` over `filter=doi:a,doi:b` (`docs/02` §5.2 names `filter=doi:`), on `P5-T12` or a small new card. It needs one more free, unkeyed recording, and its row limit is unmeasured.
   - Under rule 9, this may bear on the definition-of-done line "still returns useful candidates" without a key. I did not measure how many of the 155 Europe PMC resolves.
3. **`docs/05` §6.1's generator list (A to E) does not name Crossref**, while `P5-T12` step 1 does. I left §6.1 for `P5-T11` and `P5-T12`, which edit it.
