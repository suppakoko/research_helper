## THE OWNER'S RECORDING STEPS (for `P5-T31`, in plain words, exactly as the coordinator should relay them)

This costs nothing and takes about two minutes once you have the new key. Never paste the key into a chat message, a file or a command line. This is the tool's first run against the real Semantic Scholar service; so far it has only been tested with a fake key and a fake service.

1. **Get a new key first.** The old one counts as exposed because it was pasted into a chat on 2026-10-14. Ask Semantic Scholar for a new key and have the old one withdrawn. The form is at https://www.semanticscholar.org/product/api#api-key-form. If that page offers no way to replace a key, ask them through it. Keep the new key in your password manager.
2. **Read the plan.** In a PowerShell window, in the folder `D:\KIST\projects\research_helper`, run:
   `npm run fixtures:record -- --source semanticscholar --dry-run`
   It reads no key and sends nothing. Near the end it lists eleven requests and one hand-written answer.
3. **Open a new PowerShell window for this one session** and go to the same folder. Run this line. It asks for the key and shows stars, so paste the new key at that prompt only:
   `$env:SEMANTIC_SCHOLAR_API_KEY = [System.Net.NetworkCredential]::new("", (Read-Host "Semantic Scholar key" -AsSecureString)).Password`
   Then run: `$env:NODE_USE_SYSTEM_CA = "1"`
4. **Check the key is seen, with nothing sent:**
   `npm run fixtures:record -- --source semanticscholar --keyed --dry-run`
   It should say `Key present in SEMANTIC_SCHOLAR_API_KEY: yes` and `Nothing was sent.`
5. **Record.** Run `$env:FIXTURE_MODE = "record"`, then:
   `npm run fixtures:record -- --source semanticscholar --keyed`
   It sends 11 requests, one at a time, over about 15 seconds. It should end with `11 live request(s); 12 fixtures written`.
6. **Remove the key and close the window:**
   `Remove-Item Env:SEMANTIC_SCHOLAR_API_KEY; Remove-Item Env:FIXTURE_MODE; Remove-Item Env:NODE_USE_SYSTEM_CA`
   Then close the window.
7. **Tell me it has finished and how the last lines read.** Say nothing about the key. An agent then does the checks.
8. **Enter the new key in the plugin** through the settings pane's key dialog when you next use it. That is a separate step; this recording stores the key nowhere.

If it ends differently:
- "needs the explicit --keyed flag": add `--keyed`.
- "is not set": repeat step 3 in that window.
- "refused this request with HTTP 401 or 403": nothing was written; check it is the new key and repeat from step 3.
- "HTTP 429" or "HTTP 5xx" with a printed command: what was answered is saved; wait a few minutes and run the printed command.
- "Refusing to write fixture": stop and tell me that line. Do not retry.
