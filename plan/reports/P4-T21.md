COORDINATOR-LEVEL DECISIONS (under `plan/00` §6 item 313)
1. `both` is one run and one job record; English first, then Korean.
2. Every language is planned before any report request, so a Korean request that cannot fit fails before the English report is paid for.
3. Saving happens at the end, for both or neither.
4. `checkpoint("Composing")` is written only after the last composition, so a resume over-states and never under-states what remains.
5. Each report record holds the shared stages plus its own, so adding two records' `usage` would double-count the shared stages. Nothing adds them today.
6. `resultRef` names the first report.
7. Export and Copy act on the report shown: a "Report shown" selector appears only for two reports, first showing the interface language's report, and the suggested file name becomes `… (ko).md` only on a two-report run.
8. One group question per run, with the answer holding for both notes (`askOnce`).
9. The notice's memory is a preference, not a job-table migration, following the `cache.lastSeenPromptVersions` precedent.
10. A pause's identity is job id, pause reason, checkpoint time and attempt count.
