## What was built

- **`src/core/logger.ts`, section 6.** `LOG_RING_LINES` (5000, `docs/07` §10.4 item 4), `createLogRing` (a circular
  buffer, memory only, bounded by line count; it refuses a bound below one) and `withLogRing(sink, ring)`. That last
  one is a sink wrapper, so the ring keeps exactly the finished line the sink receives, after redaction and level
  gating. The header's "not built here" line is replaced by a dated note.
- **`src/core/diagnostics.ts` (new).** `buildDiagnostics(input)` writes one plain-text block. The header says "No API
  key and no paper content is included." Then six sections follow, in §10.4's order: environment, settings, recent
  jobs, the last log lines, recent errors and cache statistics.
  - `diagnosticsJob(record)` narrows a `JobRecord` to its pipeline, state, counts, attempt count and error code.
  - A withheld setting prints "set" or "not set".
  - The caller's withheld values are replaced by `[withheld]` wherever they occur.
  - Each line is made one line, then passed through `redact`.
  - The module is pure (`core/` imports only `model/` and `core/`).
- **`src/zotero/diagnosticsPlatform.ts` (new; not in the Files row, see the decisions).** It provides:
  - `zoteroEnvironment()`: the Zotero version, the OS, the locale and the data directory;
  - `pluginErrorLines(prefix)`: `Zotero.getErrors(true)`, filtered to the plugin's prefix;
  - `writeDiagnosticsFile` (`IOUtils.writeUTF8`);
  - `copyDiagnosticsText` (`Zotero.Utilities.Internal.copyTextToClipboard`, as the report window's Copy does).
- **`src/bootstrap/registerUI.ts`.** `registerUI` builds the ring, and wraps the log sink in it:
  `withLogRing(createZoteroLogSink(), logRing)`. `preferencesDiagnosticsPort(graph, ring)` reads every `PREFS` row
  through `getPref`. It withholds every `secret: true` row (none ships), plus `contactEmail` and `ttsLinkedFileDir`.
  It also reads:
  - the `*KeyPresent` flags, as "key …: set / not set";
  - `graph.jobs.list({})` through `diagnosticsJob`;
  - `graph.cache.stats()` while the database is open;
  - the ring;
  - the filtered errors.

  The withheld values passed to the builder are the contact address, the linked folder and the data directory.
  `logRequestBodies` is passed as `requestBodiesLogged`. `publishPreferencesHost` hands the port to the host.
- **`src/ui/prefs/preferencesPane.ts`.** It adds:
  - `DiagnosticsPort`;
  - `PreferencesHostDeps.diagnostics`;
  - three host methods, `diagnosticsText()`, `saveDiagnostics(path, text)` and `copyDiagnostics(text)`;
  - seven `PREFERENCES_L10N` ids.

- **Bundles and lists.** The 7 en-US strings are in place. ko-KR has commented drafts, not adopted. The ids are on

## Decisions (coordinator, under item 313; recorded in `docs/07` §10.4 "As built")

1. **Recent jobs carry no query and no title.** The card's step 2 ("no titles, no queries") overrides §10.4 item 3's
   "free-text query strings included".
2. **Recent errors are only the plugin's** (entries carrying `[research_helper]`, the last 100). Another add-on's
   errors, and Zotero's own, can quote a path or a title.
3. **While `logRequestBodies` is on, the log lines and the errors are left out whole**, with a line saying why (the
   card's **Do NOT**). No rule can tell which part of a line came from a body.
4. **Withheld beyond `secret: true`:** the contact address (which may appear only in the `User-Agent`) and the
   linked audio folder show as "set" or "not set". These and the data directory are replaced by `[withheld]`
   wherever else they occur.
5. **The preview is the confirmation** (§10.4: "act only when the user confirms"). Save and Copy are enabled only
   after "Show diagnostics" has put the whole text on screen under the note.
6. **A new file outside the Files row, `src/zotero/diagnosticsPlatform.ts`.** Only `src/zotero/` may name `Zotero`,
   `IOUtils` or the clipboard helper (`eslint.config.js`), and `registerUI.ts` keeps no platform code of its own.
7. **The rule-8 test is narrowed, with a dated note** (`test/unit/ui/preferencesPane.test.ts`, "rule 8: no copy
   affordance…"). The diagnostics Copy button's two attributes are the one allowed "copy" in the markup. The script
   still has no "clipboard". Its integration counterpart in `test/integration/preferences.spec.ts` ("is selected by
   Zotero.Utilities.Internal.openPreferences(paneID) … no copy affordance") is narrowed the same way: no element
   whose id contains "copy" other than `rh-diagnostics-copy`. It was missed at first, and three whole-suite runs
   failed on it, 368 passed and 1 failed each (17:26:52–17:45:34). After the fix the runs below were made.
