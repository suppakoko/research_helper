CONTRADICTIONS/FINDINGS
1. Done-when "no `[[`": I chose to scope the criterion rather than pick a fence-free fixture. The test checks both cases: the fence-free fixture has no `[[` at all, and a fenced fixture keeps its marker verbatim with none outside the fence.
2. P4-T12 (not built) is a dependency the export now rests on. The export finds §11 as the single `## ` line whose text equals the heading of `sections[number 11]`; that heading may be given with or without the `##`. §11 ends at the next level-1 or level-2 heading, so the appendices must start with `#` or `##` headings. Whatever P4-T12 puts in the bibliography slot is replaced, so its format does not matter. P4-T12's `ko` table should carry the retracted-list heading; P4-T21 passes it in.
3. The export is strict and refuses with outcome `invalid-report` (nothing written) in two cases:
   - when the bibliography's keys in index order are not exactly the cited keys outside §11, in first-appearance order;
   - when any marker outside a fence is unresolved, for example a `[[KEY]]` for an excluded item in Appendix A.

   This is the same order P4-T10's note (4) requires. P4-T18 must build `bibliography` from that same order, and P4-T12 must not use markers for excluded items in the appendices.
4. Model prose is passed through unchanged. A `zotero://` link or raw HTML that the model writes would reach the `.md` file; the export adds no `zotero://` link itself. I narrowed the docs/06 sentence to say exactly that. Whether to strip such links from model prose is an owner question; it is not carded.
5. Body markers become plain `[n]`. If the model writes `[[KEY]](...)`, the result `[n](...)` would render as a link. I did not handle this.
6. `ReportFileWriter` in `zotero/notes.ts` has the same shape as core's `ProvenanceFileWriter`. It is a separate interface, kept that way by the layering rule and the card's wording; unifying the two would be cosmetic.
7. Security:
   - The path is never logged. Log lines carry the report id and a fixed message only, never the platform error, which could quote the path; tests assert this with a path containing "private-account" and with an error message that quotes the path.
   - The export reads no field that could hold a key or an email. A test plants a key-shaped string and an email address in `warnings` and `audioScripts` and asserts neither reaches the file.
8. `safeBaseName` follows docs/08's character class exactly, so a tab or newline in a collection name becomes `-` before whitespace is collapsed. A test pins this.
