## Coordinator-level decisions

Each is recorded as DECIDED 2026-11-02 (coordinator, under `plan/00` §6 item 313) in `docs/07` §9.2's note.

1. **One `fetchEmbeddings` call is one request.** It takes at most 200 ids and throws `RangeError` above that. `ensureEmbeddings` makes the batches, so each is stored and followed by `evictToCap` before the next, and a cancel or failure keeps what arrived.
2. **A wrong-length answer is `ParseError`, and none of it is used.** `lookup` only logs this, but a bare vector has no identifiers, so a shifted one would be stored against the wrong paper for good.
3. **What counts as "without a vector".** A `null` row, a missing or `null` `embedding`, another `model`, or a `vector` that is empty or not all finite numbers. `ensureEmbeddings` adds all zeros and the wrong length. The batch's own 400 `No valid paper ids given` means the same for every id sent.
4. **768 is checked, from `docs/02` §6.9 and `docs/05` §5.2.** Both measured it on the one-paper `GET` on 2026-09-08. A stored row of another length is fetched again. A refused vector logs one warning with counts only.
5. **Scaling happens once, in double precision, before narrowing to `Float32`.** `cosine` is a dot product clamped to [-1, 1], and it throws on two models or two lengths.
6. **A failed batch degrades the run** (`docs/05` §9.1 item 4). A `ResearchHelperError` other than a cancel stops the batches and comes back as `failure`. Cancellation and programming errors propagate. A store that cannot read or write only warns, following P5-T10's cache precedent.
7. **Keys, identifiers and budget.** With no key nothing is sent, and stored vectors still come back. An arXiv work's `10.48550/arXiv.…` DOI goes out as `ARXIV:`. These calls do not draw on the run's `RequestBudget`. Reads use `getMany`, never `allForModel`.
8. **No negative cache for a paper with no vector.** It is asked about again next run inside a normal batch, never alone. `RelatedSignalKind` has no vector member, and P5-T10 left vectors out of that wrapper on purpose.

No new user-visible string was added, only English log lines, so there is no Korean draft.
