## What was done

**The spec**, `test/integration/accessibility.spec.ts`, has eight tests. For each window it:

- presses Tab through it with the focus manager, and checks that each enabled, shown control is reached once, with
  `:focus-visible`;
- computes each control's name from the DOM: `aria-labelledby`, `aria-label`, `<label>`, the XUL `label`, text,
  `title`/`tooltiptext`, and a text field's placeholder;
- sends real Escape and Enter presses through `nsITextInputProcessor`. A press that would start a networked or paid
  run hits a stand-in for the window's own `start`/`search`, so nothing runs;
- checks that each dialog button shows the label its script set from Fluent (`assertButtonLabels`);
- measures every text colour the plugin sets, in Zotero's light and dark appearance, against the composed background,
  and observes forced colours.

**Fixes** (each measured failing first):

1. **Keyboard contracts.** `addon/content/summarize.js` and `addon/content/reportWindow.js` gained an `onKey` handler
   and a `takesOwnEnter` check. The report window gained `cancelAudio`. Escape cancels a running job and stays open,
   and closes the window when idle. Enter starts the window's default action, unless focus is on a control that takes
   its own Enter, or a job runs.
2. **Names.** The radio groups `rh-search-duplicates` (`searchDialog.xhtml`) and `rh-cost-tier-choices`
   (`costConfirm.xhtml`) had no name. Each now has `aria-labelledby` pointing to its visible prompt.
3. **Dialog button labels.** Every plugin `<dialog>` showed the platform's "OK" and "Cancel".
   - **Cause:** Gecko reads `buttonlabelaccept`/`buttonlabelcancel` only while it builds the dialog, and each window set
     them later, from Fluent.
   - **Measured** without the fix: the cost dialog's accept button read "OK" for "Continue", and the key-storage
     dialog's read "OK" for "Keep keys for this session". With the fix's line removed again (the mutation run), the
     search window's accept button read "OK" for "Import 0 items", and the report window's button read "Cancel" for
     "Close".
   - **The fix:** `costConfirm.js`, `secretBackend.js`, `searchDialog.js` and `reportWindow.js` each label their
     buttons through a `labelButton` method. It sets the attribute and the rendered button's label.
4. **Contrast.** The plain Zotero accents used as text fell below 4.5:1. The before figures are in the doc's §2; the
   worst was the preferences pane's green, at 2.13:1 in light.
   - `addon/content/style/searchDialog.css` defines `--rh-text-red`, `--rh-text-orange` and `--rh-text-blue`.
     `preferences.js`'s `paintBadge` does the same inline. Each mixes the accent 55% with `--fill-primary`.
   - Borders keep the plain accent.

**Docs.** `docs/spikes/phase-7-accessibility.md` (new) holds the keyboard and names table, the contrast table, the
colour-only audit, the live regions, forced colours and the NVDA procedure. `docs/08` §9's `Unverified` marker on

  every background measured.

  themes are a system setting, left to the owner's optional NVDA step.
