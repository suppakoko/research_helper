COORDINATOR-LEVEL DECISIONS (written as DECIDED under `plan/00` §6 item 313 in `docs/06` §12.3)
1. The route is the product's own database file, read-only with Zotero closed.
2. Set ids are `small`, `medium` and `large`. The paper count is not enforced. The score prints how many listed papers the run read.
3. The format is strict: an unknown member is refused, names are at most 120 characters and notes at most 400, each on one line.
4. A set finds its runs by collection name, and its `itemKeys` are the check. A run that read a paper the set does not list is refused.
5. A run is the rows with one collection key and one date, English first. A run's id is its first report's id.
6. Answers are one document per expected theme, with id `<run id>__<expected id>` and `themeIds`.
   - An empty list means "no produced theme does".
   - A missing document is refused and is never counted as a miss.
7. Recall counts expected themes that have at least one match, once per run. Many-to-one is allowed in both directions.
8. Proxies are read from the record, not recomputed. A proxy the record lacks prints "not measured", never 0. There is no combined score and no precision figure.
9. Answers are committed, because they hold identifiers only.
