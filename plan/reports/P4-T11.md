CONTRADICTIONS/FINDINGS
1. The default CSL locale is Zotero's interface language (`ko-KR` on this machine), and the `ko-KR` CSL locale gives broken-looking text such as "홍길동와/과C. Brown" and "Lee와/과Jiho Park". So the module requires the caller to pass a locale. Which locale a Korean report should use is an open line for the owner (P4-T18 and P4-T21 apply it). An English report would pass `en-US`.
2. The visible text of each citation node is in Zotero's interface language ("Kim 등, 2024"), not the report's, because that is how Zotero's `formatCitation` works. An English report on a Korean Zotero will show Korean joiners in its Notable Papers and Bibliography nodes. P4-T13 and P4-T21 should know. Whether the note editor reformats the nodes when it opens a note was not measured.
3. docs/07 §5.2 says `BibliographyEntry.text` is "The entry as the bibliography formatter returned it". The module trims the text and removes a numeric style's own number. Without that, a renderer printing `[n]` would show "[1] [1] A. Smith". I recorded this reading in docs/01 §5.11. docs/07 was not edited, because it is not on this card's Files list. If the owner wants the number kept, docs/07's comment and the `stripStyleNumbers` call both change.
4. Which preference counts as "the user's style" is a reading, not a documented decision: the Quick Copy item format first, then `export.lastStyle`. It is recorded in docs/01 and the owner may want to confirm it.
5. The bibliography is ordered by `[n]` (first appearance) even for author-date styles such as APA, which would normally sort alphabetically. This follows D-06-7 and §9.1 ("every cited item, numbered"), but the reader will see an APA-format list that is not in alphabetical order.
6. Zotero's `formatCitation` does not escape names or titles, so an author named `O'<Brien>` would put raw markup into note HTML. The module escapes a display copy and keeps the stored item data unescaped; the integration spec checks both.
7. `Zotero.Styles` may not be loaded yet when the plugin asks. In my first two runs the first `init()` took 3.2 s and about 1.7 s, so the first bibliography of a session can wait for it. P4-T20's progress display may want to account for that.
