# Plugin icons

`addon/manifest.json` declares exactly two icon entries, and `docs/13` §1.3 fixes
both the sizes and the paths:

    "icons": {
      "48": "content/icons/favicon@0.5x.png",
      "96": "content/icons/favicon.png"
    }

This directory holds those two files and nothing else. Do not add a third size:
Zotero reads `48` and `96` only, and `NFR-18` budgets the whole XPI at 3 MB.

---

## The mark is a placeholder — read this before shipping v1.0

**The current artwork is a functional placeholder and is meant to be replaced.**
`P0-T30` shipped it so `P0-T09` could install a plugin that renders an icon
instead of a broken image. Final artwork is a design decision the project owner
has not made; replacing it belongs to the release checklist (`docs/13` §8, human
gate `G-35`). Whoever closes `G-35` should either commission a real mark or
consciously sign off on this one.

Replacing it means changing the geometry and palette constants in the generator
below and re-running it — not dropping in a hand-drawn binary, for the reason in
"Why there is no binary source".

## What it looks like

One shape, no text: a full-bleed rounded-square tile in a mid blue (`#3B6FE0`),
carrying a single white magnifier glyph — a ring plus a handle, both drawn with
the same stroke width.

Why it survives the two constraints the card set:

- **Legible at 48 px.** There is one glyph and no fine detail. At 48 px the ring
  is 19.7 px across the centreline with a 4.1 px stroke, and the handle is the
  same 4.1 px wide, so nothing in the mark is thinner than 4 px at the smaller
  size. Edges are anti-aliased over one pixel, computed from the exact signed
  distance to each shape, and **each size is rendered from scratch** rather than
  downscaled from the other — the 48 px file is a real resampling of the
  geometry, not a blurred 96 px file.
- **Works in both Zotero themes.** The tile is its own background, so the mark
  never relies on the colour behind it. `#3B6FE0` keeps roughly 4.6:1 against a
  white light-theme row and roughly 3.1:1 against a `#2B2B2B` dark-theme row —
  both above the 3:1 WCAG bar for non-text content (`docs/08` §9) — and the
  white glyph keeps roughly 4.6:1 against the tile in either theme. The corners
  outside the rounded square are fully transparent, so the tile reads as a tile
  on any background.

The icon carries no information the UI does not also state in text, so per
`docs/08` §9 it needs no alternative text of its own.

## Why there is no binary source

`.gitattributes` marks `*.png` `binary`, so git will never diff these files. A
PNG committed with no way to regenerate it is therefore a maintenance dead end:
nobody can see what changed and nobody can make a small edit. `docs/07` §2.2.1's
rule that a record must be reproducible applies to build assets too.

So the **source of truth is the script at the bottom of this file**. The PNGs are
its output. It lives in the README rather than in `scripts/` because `P0-T30`'s
`Files` list is exactly these three paths; if a later card wants it as
`scripts/make-icons.mjs`, moving the block verbatim is enough — it imports
nothing outside Node's standard library.

It deliberately adds **no dependency**. A raster-image library for two
placeholder files this size would put a transitive dependency tree into
`devDependencies` in order to draw one circle. Node's `zlib` plus about 60 lines
of PNG chunk framing is enough, and all of it is standard library.

## How to regenerate

From the repository root:

```sh
sed -n '/^```js$/,/^```$/p' addon/content/icons/README.md | sed '1d;$d' \
  > "${TMPDIR:-/tmp}/make-icons.mjs"
node "${TMPDIR:-/tmp}/make-icons.mjs"
```

Windows PowerShell equivalent:

```powershell
$lines = Get-Content addon/content/icons/README.md
$start = ($lines | Select-String -Pattern '^```js$' -List).LineNumber
$end   = ($lines | Select-String -Pattern '^```$' | Where-Object LineNumber -gt $start | Select-Object -First 1).LineNumber
$lines[$start..($end - 2)] | Set-Content -Encoding utf8 "$env:TEMP\make-icons.mjs"
node "$env:TEMP\make-icons.mjs"
```

Copying the block into a `.mjs` file by hand works just as well. The script
writes into `addon/content/icons` relative to the current directory; set
`ICONS_OUT_DIR` to write somewhere else, which is how you compare against the
committed files without overwriting them.

## Expected output

Generated with Node v22.23.0 on 2026-09-10:

```text
favicon.png       96x96  1723 bytes
  sha256 48e9ad942a057712b4ba41b1363c81e853806c8bd41eabe76319fed018e1064a
favicon@0.5x.png  48x48   861 bytes
  sha256 aad6e9a1f5258ab07522315a0d401c6b01845f82688eb699cdedfe0df9994086
```

Check with `sha256sum addon/content/icons/*.png`.

**If those hashes differ but the images look identical**, the cause is almost
certainly the deflate implementation, not the drawing. Every pixel this script
computes comes from `+ - * /` and `Math.sqrt`, all of which IEEE-754 specifies
exactly, so the *uncompressed* image is identical on every platform and every
Node version; the compressed byte stream inside the `IDAT` chunk is whatever the
`zlib` bundled with your Node produces. To tell the two cases apart, compare the
decoded pixels rather than the files:

```sh
node --input-type=module -e '
  import { readFileSync } from "node:fs";
  import { inflateSync } from "node:zlib";
  import { createHash } from "node:crypto";
  for (const f of ["favicon.png", "favicon@0.5x.png"]) {
    const b = readFileSync(`addon/content/icons/${f}`);
    let o = 8; const d = [];
    while (o < b.length) {
      const n = b.readUInt32BE(o);
      if (b.toString("ascii", o + 4, o + 8) === "IDAT") d.push(b.subarray(o + 8, o + 8 + n));
      o += 12 + n;
    }
    console.log(f, createHash("sha256").update(inflateSync(Buffer.concat(d))).digest("hex"));
  }'
```

which must print:

```text
favicon.png 726553c5dd34b0bc2ae3d113ab4acb6e7cbf2f2d5b217b76512cbf7f3eff80d1
favicon@0.5x.png f94b602777e4cc29e90fb59fd4f8971820148cfc621992ed31b57a1303498747
```

If the pixel hashes match, the images are identical and only the compression
differs: commit the regenerated files and update the file hashes above in the
same commit.

## The generator

```js
// research_helper plugin icon generator - deterministic, dependency-free.
// Node >= 22. Writes favicon.png (96x96) and favicon@0.5x.png (48x48).
//
// The mark: a full-bleed rounded-square tile in a mid blue, carrying one white
// magnifier glyph (ring + handle). The tile is its own background, so the mark
// does not depend on the surrounding theme; the glyph is white on blue, which
// is the same contrast in Zotero's light and dark themes.
//
// Every pixel comes from + - * / and Math.sqrt, all exactly specified by
// IEEE-754. No transcendental function (sin/cos/pow), whose result is
// implementation-defined, is used, so the rendered image is bit-for-bit
// reproducible on any platform.

import { deflateSync, constants } from "node:zlib";
import { mkdirSync, writeFileSync } from "node:fs";
import { join } from "node:path";

const OUT_DIR = process.env.ICONS_OUT_DIR ?? "addon/content/icons";

// ---------------------------------------------------------------- palette ---
// Tile blue. Chosen so the tile keeps >= 3:1 contrast against both a white
// (light theme) and a near-black (dark theme) list background, and so the white
// glyph keeps ~4.6:1 against the tile.
const TILE = [0x3b, 0x6f, 0xe0];
const GLYPH = [0xff, 0xff, 0xff];

// --------------------------------------------------------------- geometry ---
// All coordinates are normalized to the unit square, y down, so the same
// numbers drive both sizes.
const CORNER = 0.22; // tile corner radius
const RING_CX = 0.455;
const RING_CY = 0.459;
const RING_R = 0.205; // radius of the ring's centreline
const STROKE = 0.0425; // half the stroke width, shared by ring and handle
const HANDLE_AX = 0.6;
const HANDLE_AY = 0.604;
const HANDLE_BX = 0.755;
const HANDLE_BY = 0.759;

const clamp01 = (v) => (v < 0 ? 0 : v > 1 ? 1 : v);

// Signed distance to a rounded square centred on (0.5, 0.5), half-extent 0.5.
function sdTile(x, y) {
  const qx = Math.abs(x - 0.5) - (0.5 - CORNER);
  const qy = Math.abs(y - 0.5) - (0.5 - CORNER);
  const mx = qx > 0 ? qx : 0;
  const my = qy > 0 ? qy : 0;
  const outside = Math.sqrt(mx * mx + my * my);
  const inside = Math.min(Math.max(qx, qy), 0);
  return outside + inside - CORNER;
}

// Signed distance to the magnifier ring (an annulus).
function sdRing(x, y) {
  const dx = x - RING_CX;
  const dy = y - RING_CY;
  return Math.abs(Math.sqrt(dx * dx + dy * dy) - RING_R) - STROKE;
}

// Signed distance to the handle (a capsule with round caps).
function sdHandle(x, y) {
  const bax = HANDLE_BX - HANDLE_AX;
  const bay = HANDLE_BY - HANDLE_AY;
  const pax = x - HANDLE_AX;
  const pay = y - HANDLE_AY;
  const t = clamp01((pax * bax + pay * bay) / (bax * bax + bay * bay));
  const cx = pax - bax * t;
  const cy = pay - bay * t;
  return Math.sqrt(cx * cx + cy * cy) - STROKE;
}

// Distance -> coverage. One pixel of linear anti-aliasing, which is what keeps
// the 48 px rendering readable rather than jagged.
const coverage = (d, size) => clamp01(0.5 - d * size);

function renderRGBA(size) {
  // One filter byte (0 = None) per scanline, then RGBA left to right.
  const raw = Buffer.alloc(size * (1 + size * 4));
  for (let py = 0; py < size; py++) {
    const rowStart = py * (1 + size * 4);
    raw[rowStart] = 0;
    const y = (py + 0.5) / size;
    for (let px = 0; px < size; px++) {
      const x = (px + 0.5) / size;
      const tile = coverage(sdTile(x, y), size);
      const glyph = coverage(Math.min(sdRing(x, y), sdHandle(x, y)), size);
      const o = rowStart + 1 + px * 4;
      for (let c = 0; c < 3; c++) {
        raw[o + c] = Math.round(TILE[c] + (GLYPH[c] - TILE[c]) * glyph);
      }
      raw[o + 3] = Math.round(tile * 255);
    }
  }
  return raw;
}

// ------------------------------------------------------------- PNG writer ---
const CRC_TABLE = (() => {
  const t = new Int32Array(256);
  for (let n = 0; n < 256; n++) {
    let c = n;
    for (let k = 0; k < 8; k++) c = c & 1 ? 0xedb88320 ^ (c >>> 1) : c >>> 1;
    t[n] = c;
  }
  return t;
})();

function crc32(buf) {
  let c = -1;
  for (let i = 0; i < buf.length; i++) {
    c = CRC_TABLE[(c ^ buf[i]) & 0xff] ^ (c >>> 8);
  }
  return (c ^ -1) >>> 0;
}

function chunk(type, data) {
  const head = Buffer.alloc(8);
  head.writeUInt32BE(data.length, 0);
  head.write(type, 4, "ascii");
  const crc = Buffer.alloc(4);
  crc.writeUInt32BE(crc32(Buffer.concat([head.subarray(4), data])), 0);
  return Buffer.concat([head, data, crc]);
}

function encodePNG(size, raw) {
  const ihdr = Buffer.alloc(13);
  ihdr.writeUInt32BE(size, 0);
  ihdr.writeUInt32BE(size, 4);
  ihdr[8] = 8; // bit depth
  ihdr[9] = 6; // colour type 6 = truecolour with alpha
  ihdr[10] = 0; // compression method: deflate
  ihdr[11] = 0; // filter method: adaptive
  ihdr[12] = 0; // no interlace
  const idat = deflateSync(raw, {
    level: constants.Z_BEST_COMPRESSION,
    strategy: constants.Z_DEFAULT_STRATEGY,
    memLevel: 8,
    windowBits: 15,
  });
  return Buffer.concat([
    Buffer.from([0x89, 0x50, 0x4e, 0x47, 0x0d, 0x0a, 0x1a, 0x0a]),
    chunk("IHDR", ihdr),
    chunk("IDAT", idat),
    chunk("IEND", Buffer.alloc(0)),
  ]);
}

mkdirSync(OUT_DIR, { recursive: true });
for (const [size, name] of [
  [96, "favicon.png"],
  [48, "favicon@0.5x.png"],
]) {
  const png = encodePNG(size, renderRGBA(size));
  writeFileSync(join(OUT_DIR, name), png);
  process.stdout.write(`${join(OUT_DIR, name)}  ${size}x${size}  ${png.length} bytes\n`);
}
```
